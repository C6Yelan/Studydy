# Studydy 論文與網站來源討論紀錄

更新日期：2026-10-17，Asia/Taipei。

目前論文改善已完成並部署；一般網站仍在設計討論階段。使用者希望先一次討論完各部分，再統一進行實作與隔夜大測試。本文件作為接續討論的固定入口，區分既有成果、設計提案與未定事項；本次僅保存紀錄，未啟動新一輪網站實作、隔夜測試或排程。

## 已確認的工作原則

- 這項研究功能本來就是耗時任務，以內容品質優先；耗時與請求次數是紀錄項目，不是降低品質或提早結束的理由。
- 避免驗證過於嚴格，造成有用來源大量被排除。單篇、預印本、小樣本、理論、個案與相反結果都可以有用途，應保留適用條件及限制。
- 不擅自要求使用者未指定的精確數值、固定篇數、普遍外推、完整實作或統一研究方法。
- 改善須適用一般情境，不針對測試題目、特定論文或少數網站硬寫例外。
- 區分搜尋成功、取得正文、內容有用、可匯入與引用可回查；HTTP 成功、結構化回應合法或模型自評皆不單獨代表品質通過。
- 淘汰舊機制時直接更新現行流程，保留必要的歷史資料與來源關係，不另留一套可切換的舊流程。
- 延續 [共通工作規則](../../AGENTS.md) 中既有的 Luna、虛擬教材與必要驗證後部署授權，不將紀錄整理變成重新逐項批准的關卡。使用者本次要求先繼續討論，再統一啟動後續工作。

## 論文部分已完成的內容

從主題建立教材與補充學習共用需求確認，確認觀念及細節後才開始研究。搜尋使用 OpenAlex 自然語言語意查詢；Crossref 保留 DOI 摘要補查。Semantic Scholar 與 Unpaywall 有既有支援，但本輪環境未啟用。

取得流程優先使用同版本 PDF，保留圖表與排版；第一次閱讀前可嘗試索引已列明、符合匯入條件的其他公開版本，記錄取得版本，不能替換已讀原檔。PDF 失敗時可採同篇可核對的 HTML 正文；摘要頁不冒充完整正文。閱讀內容保存為 PDF 或網頁文字快照，選用與匯入沿用同一份內容。

研究閱讀會核對方法、研究對象、結果與限制，區分模擬預測、觀察關聯、因果證據與作者解釋。部分支持仍可採用；已有答案但存在具體方法或反例疑點時，可以繼續查證。續接舊工作時，政策不同的涵蓋快取會重核，已讀原文與引用保留。

## 實際改動的層次

| 層次 | 本輪實際狀態 |
| --- | --- |
| 搜尋與取得 | 主要修改範圍，包含語意搜尋、來源入口、替代版本、HTML 補救與快照 |
| 來源去重 | DOI、arXiv 版本、URL 與正文指紋的原有規則保留；合併流程只配合快照清理相關狀態，未新增語意去重 |
| 研究階段的分析 | 有修改選讀段落、支持與限制判斷、缺口補查、停止及涵蓋快取規則 |
| 正式教材分析 | 未修改概念抽取、知識結構生成、教材概念去重或合併的核心演算法 |
| Evidence 與引用定位 | 沿用既有原文、頁碼與區塊的一致性檢查，未放寬 |

正式分析程式未改，但送入的來源與選讀段落可能不同，因此最後教材內容可能改變。不能把「未改分析程式」說成「完全不影響分析結果」。

最後一輪部署修改的研究 runtime 為 `research_sources.py`、`research_reading.py`、`research_web.py`、`research_documents.py`、`research_workflow.py`。前一輪另包含需求確認入口、工作生命週期及資料表調整，詳見部署紀錄。

## 一般網站目前的機制與能力邊界

一般網站目前較準確的定位是可嘗試公開網址的靜態正文擷取，加上有限搜尋入口與補救機制，尚未驗證成能穩定處理各類網站的通用讀取能力。

| 部分 | 現況 |
| --- | --- |
| 搜尋順序 | 一般需求目前強制先查論文，缺口再補查網站；指定網址則先讀原頁 |
| 搜尋入口 | 自架 SearXNG 啟用 Yahoo、Wikipedia、Wikibooks；明確 Python／網頁技術查詢另有 Python 文件與 MDN 入口 |
| 正文取得 | HTTP 取得 HTML，以 Trafilatura 擷取文字、標題、表格及程式碼；正式流程沒有 JavaScript 瀏覽器渲染，圖片本身未納入這條文字擷取流程 |
| 替代入口 | 沿原頁 PDF、RSS／Atom 等連結取得；非論文仍保留由模型提出同站替代網址再嘗試的步驟 |
| 同篇核對 | RSS 已依原文章網址核對；一般替代 HTML 的同篇核對仍需補強，同站不保證是同一文章 |
| 匯入條件 | 主要依少數 HTML 授權標記辨識；可讀但未確認匯入條件時，通常轉成參考來源並停止深入閱讀，內容價值與匯入條件綁得太緊 |
| 閱讀與保存 | 符合條件的內容沿用研究閱讀、來源快照、轉檔與 Evidence 流程 |

一般網站尚未完成本輪專項的跨類型真實驗收，不能沿用論文數字宣稱網站成功率。

另有 [2026 年 10 月 7 日公開來源取得比較](research-acquisition.md)：十個固定樣本曾比較 direct HTTP、官方路徑與 Chromium，當時未將 Chromium 接入正式流程。那是舊版本、小型目的性選樣，不能當成目前全網能力或現在一定需要瀏覽器的證明；後續可檢查其工具與證據是否仍適用。

## 論文限定與混合來源的產品選擇

使用者上傳教材加論文補充，可以形成研究導向的完整產品；現有知識地圖、問答、概念卡與 Podcast 不依賴一般網站自動搜尋才能運作。

但論文未必能單獨滿足從零建立基礎、循序例題、工具操作、API 版本、現行制度或公告等需求。論文限定也只是使用可取得且符合匯入條件的一部分論文，不等於完整學術資料庫。

目前設計討論採用的暫定方向是「使用者教材、論文、官方文件與開放教材為主，一般網站補具體缺口」。這是助理建議與設計假設，尚未實作，也未把「移除一般網站」當成使用者已定案的決定。

即使最後選擇論文限定，也仍需保留出版社 HTML 正文與典藏入口；來源類型的收斂不等同刪除所有 HTML 讀取能力。

## 網站設計調整提案

### 第一批 依需求安排來源

在同一條研究流程中，依已確認的子題安排來源，不讓搜尋重新拆解或擴張需求。

| 學習需求 | 優先來源 |
| --- | --- |
| 原理、研究結果、方法比較 | 論文與綜述 |
| 基礎定義、循序理解、例題 | 開放教材與教育機構教材 |
| 操作、API、設定、版本差異 | 原發布者的官方文件 |
| 閱讀指定文章 | 使用者指定來源 |
| 尚缺的必要內容 | 有針對性的一般網站補查 |

優先順序不是來源淘汰名單，也不要求每題找齊所有類別。官方文件不能只等同寫死的 Python、MDN 幾站，需依問題找到原發布者及可回查依據。

主要調整 `research_workflow.py` 的初始計畫與後續補查，利用現有 `papers`／`web` 管道，直接取代強制論文優先的邏輯。需求確認、子題索引、來源選用與教材版本流程沿用。

### 第二批 取得與判讀網站內容

- 以原頁實際公布的文件、RSS、列印版等入口取代模型憑慣例猜網址。
- 核對替代入口與原文章的關係，避免讀到首頁、文章列表或另一篇文章。
- 區分正文、摘要、登入頁與分頁，保留實際取得的範圍；不能把不同文章拼成同一來源。
- 核對適用的站台正式授權說明，改善只依固定頁面標記判斷的缺點。
- 沿用不可變內容快照與既有轉檔／Evidence 綁定，確保匯入內容就是研究時閱讀的內容。

既有欄位可先承接三項不同判斷：`access` 表示取得狀況，`review` 表示內容用途與限制，`eligible` 表示能否匯入。可參考內容不因無法全文匯入而失去價值；是否能納入教材仍依具體來源條件處理。

判讀按內容用途調整：官方文件核對版本與操作條件，教學核對步驟與例外，研究核對方法與限制，個人經驗保留情境。缺作者、日期或實驗不能自動套用成通用淘汰門檻。

主要涉及 `research_sources.py`、`research_reading.py`、`research_web.py`，來源快照、轉檔及教材分析流程共用，不另建一套研究系統。

### 第三批 依實例擴充搜尋與動態讀取

重要來源找不到時，檢查查詢與搜尋供應商；來源找得到但正文確實依賴 JavaScript 時，再加入受控瀏覽器讀取；已取得內容卻無法支持需求時，補查其他證據。新增能力應對應實際缺口，不以引擎數或候選數增加宣稱品質提升。

使用者介面沿用確認與選材，優先顯示來源補足哪個觀念、原文支持程度、版本與限制；不將引擎或擷取器的設定負擔交給使用者。

## 後續整體實作與隔夜測試待整合項目

使用者要先完成各部分討論，再統一安排實作與大測試。後續討論持續補入本文件，屆時整理成具體範圍與驗收清單；目前不將以下項目當成已開始的任務。

- 最終來源策略採論文限定或混合來源，以及一般網站的產品承諾範圍。
- 接下來要討論的其他功能與層次；目前沒有新增正式教材分析或概念去重改造的決定。
- 選定基礎學習、研究比較與實作操作等真實需求，對照論文限定與混合來源的必要內容、來源適用性及缺口。
- 網站案例需涵蓋公開靜態頁、指定網址、分頁、同篇替代入口、版本差異、短而有用的內容、來源條件辨識，以及有證據需要處理的動態頁。
- 分開驗證找到來源、取得正文、閱讀判斷、可匯入範圍、引用定位與最後教材品質，不能用單一總分掩蓋問題。
- 保留有用但有限的資料；錯文件、引用不符或取得失敗如實回報，不以降低門檻換取全數通過。
- 隔夜執行應保存進度、真實模型請求、失敗與重試，以及可交付成果；不得只有持續重試或最後一句成功。
- 具體開始時間及整包執行內容等後續討論完成再確定，既有資料保護、共用依賴與 Git 操作邊界依共通規則維持。

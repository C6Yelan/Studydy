## 工作範圍與共通原則

補充學習與從主題建立教材，在確認學習範圍後共用研究工作、搜尋、正文閱讀、選材、來源保存及教材處理流程。範圍、程度與連貫性都是兩邊的要求；補充學習多參考原教材，從主題建立則依已確認需求與先備判斷，不能一律視為入門。共用流程改善一次，兩個入口分別驗收。

本輪重點是正式分析前的需求理解、來源取得、選材、片段比較與上下文管理，以及成果交接。正式教材分析、概念去重、知識結構與地圖生成維持既有基線；有具體失敗、退化或新需求證據時，再針對問題修正，不主動重寫整套分析。

- 品質優先。耗時、請求數與 token 用量用來觀察成本，不作降低品質或提早結束的理由；也不為零散缺漏無限搜尋。
- 不擅加使用者未要求的固定篇數、精確數值、普遍外推、完整程式、研究方法或完整課綱。
- 單篇、預印本、小樣本、理論、個案及相反結果都可能有用，按用途保留條件與限制，不作通用淘汰理由。
- 分開判斷取得成功、內容有用、可匯入與引用可回查。HTTP 成功、JSON 合法及模型自評都不單獨代表品質通過。
- 原文、版本、頁碼與區塊關係保持可回查；不以模型摘要冒充來源，不默默改寫或刪除原始教材。
- 改善適用一般情境，不針對測試題目或少數網站硬寫例外。替換舊機制時更新現行流程，不另保留無必要的可切換舊流程。

既有 Luna、虛擬教材外送與必要驗證後部署授權依 [共通工作規則](../../AGENTS.md) 持續有效。使用者目前明確要求先討論與記錄，尚不開始新一輪工作；開始後，一般範圍內的修正、重試與部署不逐項重問批准。DB、原檔、共用依賴、憑證及 Git 操作邊界仍依共通規則保護。

## 已整理的產品方向

以下為後續工作的設計依據，不表示功能已接入正式站。尚需實驗選擇的方法另列於架構與方案章節。

### 原始需求與待確認概念表

概念表是可修改的學習範圍，包含名稱、程度、目標、觀念與細節、排除範圍，不是正式教材分析後的知識地圖。

- 保留完整原意，整理到容易確認即可；避免漏掉後半段需求、過度細拆、重複比較項目或擅加負擔。
- 尊重混合先備，例如「會 Python，但初次接觸 RAG」，不壓成全面入門或全面進階。必要先備適量補充，不另擴成完整課程。
- 資訊不足時先提供合理、可修改的提案，沿用確認畫面；只有不同解讀會明顯改變學習方向時才釐清，不新增例行多輪追問或必填背景。
- 使用者編輯確認後的範圍主導後續搜尋與選材。原始需求協助理解背景，不能用來加回刪掉的項目或推翻後來的調整。
- 既有教材的概念、重點與關係只協助定位，不得主導或擴張使用者本次要求。

### 依需求安排來源

採混合來源方向：使用者教材、論文、官方文件與開放教材為主，一般網站補具體需求；不強制所有問題先查論文，也不移除一般網站。

| 學習需求 | 優先來源 |
| --- | --- |
| 原理、研究結果、方法比較 | 論文與綜述 |
| 基礎定義、循序理解、例題 | 開放教材與教育機構教材 |
| 操作、API、設定與版本差異 | 原發布者的官方文件 |
| 閱讀指定文章 | 使用者指定來源 |
| 尚缺的必要內容 | 有針對性的一般網站補查 |

這是搜尋優先順序，不是淘汰名單，也不要求每題湊齊所有類別。官方來源要依問題尋找，不能只寫死 Python、MDN 等少數網站。出版社 HTML 正文與典藏入口仍屬論文取得的一部分。

網站取得沿原頁實際公布的 PDF、RSS、列印版等入口，核對與原文章的關係，逐步替換模型憑慣例猜網址的做法。同站不代表同篇；正文、摘要、登入頁與分頁須分清，不能把不同文章拼成同一來源。匯入沿用研究時的不可變快照。

內容價值與匯入條件分開判斷，核對適用的站台正式授權說明，不只依固定頁面標記。可參考但不能匯入的內容不能冒充可交付教材。判讀按用途調整：官方文件核對版本與操作條件，教學核對步驟與例外，研究核對方法與限制，個人經驗保留情境；缺作者、日期或實驗不是一律排除的理由。

### 選材與補充價值

流程以「文件相關性 → 相關原文及必要上下文 → 與既有及本次來源比較 → 實際送入範圍」為方向。完全相同的文件或片段可提前重用；語意近似內容待有足夠上下文再比較。

文件資訊不足時補看目錄、導讀或可能相關的正文，不因缺摘要、用詞不同或大部分偏題就排除整份文件。長文只選相關小節也可以；全篇相關時可全文送入，不固定截取前幾頁或限制選取比例。保留理解所需的定義、前提、方法、限制、圖表與程式碼。

| 比較結果 | 處理方向 |
| --- | --- |
| 相同原文、鏡像或轉載 | 保留代表內容，保留其他來源對應 |
| 不同措辭但可確認資訊等價，且無本次需要的新用途 | 略過重複分析，不能只靠相似度判定 |
| 同概念但新增步驟、推導、例子、解法、版本或條件 | 保留有用差異與必要上下文 |
| 不同研究得到相近結果 | 保留有用途的獨立證據與研究條件；不能把綜述轉引當成獨立研究 |
| 相反結果、否定、數值、單位、公式或程式差異 | 核對並保留差異，不因表面相似而合併 |
| 是否等價仍不確定 | 按需補讀或保留，接受少量重複，不反覆要求證明新增價值 |

補充學習需分開看「原教材是否已涵蓋」與「本次是否有學習價值」：已講過定義，仍可接受使用者要求的例子、更新或查證。新概念數量不代表補充成效。原始 PDF 有內容但目前教材未有效呈現時，先辨識能否沿用既有來源補足，不直接視為需求已滿足。

概念、重點與關係目前不穩定，因此比較只輔助選材，不要求先建立完整正確的知識基準。明確重複才略過；相關有用但判不清是否新增的內容可保留。未命中檢索不代表原教材沒有，概念重合也不代表已教清楚。原文若擷取不完整，同樣不能作可靠的排除依據。

從主題建立教材沒有舊教材可比較，但仍比較本次來源之間的重複。多份基礎定義可以保留代表內容，不能全部刪掉而讓教材缺少前提。兩種入口都檢查最後實際送入的區塊，避免相鄰段落或圖表頁展開後重新帶回大量重複。

### 資料分歧與地圖呈現

系統負責比較並提供有依據、適用範圍清楚的教學結論，不只並列矛盾內容讓使用者選邊。

1. 先核對版本、對象、條件，以及擷取或摘要失真，釐清表面矛盾。
2. 有依據確認過時、誤引或不適用時，說明原因，以適用內容作主要教學說明；來源較新、官方身分或模型偏好都不能單獨觸發取代。
3. 確實無定論時，整理已知部分、影響結果的條件與未確定範圍，例如「在 X 條件下較支持 A；換成 Y 條件時結果仍不一致」。
4. 保留新舊來源與判斷依據，整理後的結論不能冒充來源原文。

只核對影響本次學習的具體差異，不對整份教材做全面一致性審查，也不以消除所有分歧作交付門檻。

地圖與概念主內容呈現整理後的結論及必要條件；一般版本差異、研究限制、不同例子與判斷理由放在詳細內容及來源說明。只有比較理論、方法或版本本身屬學習目標時，才考慮分開呈現；不為每篇來源或每個分歧新增節點、關係線。

條件與限制必須隨原文交接，問答、概念卡與 Podcast 的回歸要確認不會將不同條件下的說法混成無條件結論。這是來源接入驗證；教材問答本身是否新增改善工作，另待討論。

### 停止追查與部分交付

- 來源持續無法取得就停止追查、略過，不因重要而反覆重試或追逐替代入口，也不讓後續自動補查重新追同一失敗來源。保留原因，不刪除原始教材；使用者要求重試或提供新入口時另行處理。
- 有可用且能形成可理解補充的內容，就交付已有成果，不要求所有來源與需求皆成功。
- 主要概念仍缺失且有其他具體可行線索時才繼續查證；沒有可行線索就結束，不為零散缺漏持續搜尋。
- 沒有適合加入的內容時，正常回報「本次未找到適合加入的補充」，不建立空追加版本。不能因不可靠的既有結構顯示已涵蓋，就斷定沒有新增價值。
- 匯入或分析失敗須與正常無新增結果分開。已選出有用內容卻處理失敗，不能改稱沒有補充價值；其他可用成果不因單一來源失敗而全部扣住，整批失敗不得宣稱完成。

使用者只看到**整個主要學習概念缺失**的簡短說明，例如「本次尚未補足模型評估方法」。主要概念依已確認需求判斷，不依不穩定地圖節點或模型細拆項目認定。零散細節、缺少額外例子及逐筆來源失敗留在內部紀錄，不新增缺口清單或地圖警示。

不顯示細項缺口不等於標成已涵蓋；影響正確性的適用條件直接寫進教學說明。內部仍區分未找到證據、取不到、不能匯入、沒有新增價值與處理失敗。

### 使用者修正選材

沿用來源選用介面，讓使用者取消來源、要求納入某份來源或調整補充方向。平常顯示與本次需求相關的簡短理由，例如「原教材已有定義，本來源補上判斷條件與例題」，不只給價值分數，也不主動展示所有排除細節。

不要求逐段批准。指定納入仍需取得可用內容並符合來源與匯入契約，不能把選用操作當成已讀或已匯入成功。

### 上下文管理的候選方法

研究閱讀每次約 6,000 字元，`previous_notes` 可能累積；涵蓋核對有分題與快取，但新證據加入同題時仍可能重送舊摘錄。現有證據批次約 32K 估算 tokens、未讀線索約 6K、整體輸入約 48K，已有容量保護。本次架構檢查尚未量測新一輪實際輸入峰值；本機保存量不等於模型輸入量。

已納入隔夜工作的是降低無效上下文消耗，**RAG 與逐份建索引只是候選方法**：

1. 先量測，再比較有界閱讀筆記、定位線索與按需取回原文，減少累積內容重送。
2. 新片段只與可能重複、補充或相反的既有原文比較；檢索用來找候選，不作刪除裁決。
3. 確有反覆檢索大量研究來源的需要時，評估取得正文或完成選讀後建立任務內索引，優先重用現有切段、排序與資料庫能力，維持與正式教材的資料邊界。
4. 不為建立索引先把所有候選正式分析一次，也不在原有完整輸入上無差別追加檢索。新來源仍需獨立做必要選讀，未命中不能當成不相關。

2026-10-13 的 24 次歷史 RAG 對照，是在完整批次上額外加入檢索，估算輸入由 58,756 增至 77,734 tokens，增加 32.3%，品質收益不穩定，因此未接入正式分析。它不是「檢索替代大量歷史上下文」的對照，不能據此否定新方向，亦不能宣稱新方向有效。詳見 [測試文件](testing.md)。

### 網站能力與限流的處理範圍

網站改善優先處理需求導向搜尋、實際入口、同篇核對與來源條件。重要來源找不到時才檢查查詢或搜尋供應商；來源確實依賴 JavaScript 時才評估受控瀏覽器。是否新增引擎或瀏覽器由案例證據決定，不列為無條件必做項目。

目前抓取接受 200 後再判讀正文；301／302／303／307／308 會跟隨導向，整鏈最多 5 次請求。403 記阻擋；429 按 `Retry-After` 冷卻，缺少時預設 60 秒；503 有該標頭才延後。其餘非 200 通常記一般 HTTP 失敗。另有部分驗證頁、登入頁及正文不足辨識，先沿用後續分析，不為辨識所有網站新增全面驗證機制。

| 補回兩篇論文的閱讀 | 兩篇均保留，區分植被覆蓋恢復與存活樹木生長韌性，保留不同結果與條件；引用定位均通過 |
| HTML 來源定位 | Frontiers 真實正文 65 段經文字轉 PDF 後對回 16 頁區塊；這些是轉檔後頁碼 |
| 真實模型請求 | 本輪完整流程、受控案例與重核、兩篇補回來源閱讀，共 207 次 Luna 請求完成；不包含整個長任務的所有歷史請求 |

部分出版社仍回傳 403，部分需求仍有證據缺口。這些限制如實保留；論文部分在本次約定範圍內已結案，不表示所有論文都可取得或所有題目都有完整答案。

詳細依據見 [測試文件](testing.md)、[架構文件](architecture.md) 與 [部署文件](deployment.md)。本機部署與驗證紀錄位於 `data/deployments/research-scope-20261016T140548Z/` 及 `data/deployments/research-quality-20261016T162315Z/`，原始驗證內容不加入 Git／CI。

### 前一輪實際改動範圍

| 層次 | 本輪實際狀態 |
| --- | --- |
| 搜尋與取得 | 主要修改範圍，包含語意搜尋、來源入口、替代版本、HTML 補救與快照 |
| 來源去重 | DOI、arXiv 版本、URL 與正文指紋的原有規則保留；合併流程只配合快照清理相關狀態，未新增語意去重 |
| 研究階段的分析 | 有修改選讀段落、支持與限制判斷、缺口補查、停止及涵蓋快取規則 |
| 正式教材分析 | 未修改概念抽取、知識結構生成、教材概念去重或合併的核心演算法 |
| Evidence 與引用定位 | 沿用既有原文、頁碼與區塊的一致性檢查，未放寬 |

正式分析程式未改，但送入的來源與選讀段落可能不同，因此最後教材內容可能改變。不能把「未改分析程式」說成「完全不影響分析結果」。

最後一輪部署修改的研究 runtime 為 `research_sources.py`、`research_reading.py`、`research_web.py`、`research_documents.py`、`research_workflow.py`。前一輪另包含需求確認入口、工作生命週期及資料表調整，詳見部署紀錄。

# 教材處理

[文件入口](../README.md) · [使用指南](usage.md) · [系統架構](architecture.md)

## 來源與轉檔

教材是具名的來源集合。文件與一組圖片上限 100 MiB、音訊 300 MiB、影片 2 GiB，轉換後 PDF 上限 100 MiB；音訊與影片長度上限 2 小時。格式能力由 `/v1/source-capabilities`（`source-capabilities/v2`）宣告，含格式種類與單次請求上限。超過單次請求上限（正式站 90 MiB）的檔案由瀏覽器依序分段送到 `/v1/materials/{id}/source-parts`，暫存在 artifact 磁碟的 `.media-work/uploads`，收齊後才建立來源；同一意圖重送最後一段不會重複建立。中斷超過一天的分段上傳，以及程序被終止後留在 `.media-work` 的轉換暫存（原檔副本、YouTube 音軌、沙箱輸出），由維護 worker 清除。

| 格式 | 處理與定位 |
| --- | --- |
| PDF | 驗證原檔、建立預覽與 mapping，使用原頁碼 |
| DOCX | LibreOffice Writer 轉 PDF；使用轉換後頁碼，段落對照可能有歧義 |
| PPTX | LibreOffice Impress 轉 PDF；排除 hidden slides／notes，保留原投影片編號 |
| DOC／PPT | 檢查二進位 Office 格式再轉 PDF；僅提供轉換後頁碼 |
| UTF-8 TXT | 有界換行排版；保存原行號及 PDF 頁碼 |
| Markdown | 限制 HTML 排版；raw HTML 顯示為文字、不載入圖片，保存 block 及 PDF 頁碼 |
| 圖片 PNG／JPG／WebP | 一次最多 50 張、可調整順序，合成一份來源：第幾張即第幾頁，交由 OCR 辨識文字 |
| 音訊 MP3／M4A／WAV | 本機語音辨識成逐字稿，約每 2 分鐘一頁；來源從該時間段播放原音 |
| 影片 MP4 | 上傳時只抽出音軌保存、原影片不保存，之後與音訊相同；來源只播音軌 |
| YouTube 連結 | 只保存影片參照、逐字稿與分析結果；來源以 YouTube 內嵌播放器從該時間播放 |

原檔、PDF 與 mapping 各自保存 hash。下載使用原 MIME 與 attachment，PDF 預覽使用獨立入口。解析在 Bubblewrap 子程序內執行，唯讀掛載 runtime 及輸入，僅輸出／暫存可寫。只有 DOCX／PPTX 的受控圖片準備階段可連線，實際 Office 與 PDF 解析始終在斷網沙箱；超連結保留，其他 HTTP(S) 外部素材在轉檔副本內盡力取得並內嵌，失敗或超出下載限額就略過，不因此拒絕整份文件。原檔不改寫；其餘格式仍不連線。資源限制、版本檢查與禁止的主動內容見 [converter.py](../backend/src/document_normalization/converter.py) 及 [renderer.py](../backend/src/document_normalization/renderer.py)。失敗來源按「重試轉換」時使用現行轉檔政策，已完成來源的快照保持不變。

## 帳號空間

每個帳號總空間上限 5 GiB（介面標示 5 GB；`storage_usage.ACCOUNT_STORAGE_LIMIT_BYTES`）。上限是「接受新增工作」的門檻：已接受的工作產生的檔案（成品比預估大、normalized_pdf／mapping／分析檔、補充學習匯入）照常完成、不會中途中斷，但都計入已用並擋住之後的新增。

已用＝該帳號全部 artifacts（原檔、normalized_pdf、source_mapping、Podcast 音訊與影片）＋`analysis/<learner>/` 分析檔目錄＋保留額度（`storage_reservations`，0020）。artifacts 與保留在同一個 SQL 敘述加總，背景同時提交成品時不會漏算。保留額度在接受工作時固定：上傳以本次大小、分段上傳以第一段宣告的整檔大小（之後各段不得超過）；建立 Podcast 時每集保留音訊估值，勾選影片的另保留影片估值；重試、補建或手動生成影片時每集保留影片估值。估值取當下全站既有同類成品（`podcast_audio`／`podcast_video`）的平均大小，尚無成品時用 20 MiB／64 MiB，之後全站平均變動不影響已保留的額度。成品寫入的同一交易刪除該工作的保留、改計實際大小。各用途的保留生命週期如下：

- 上傳：同一意圖只有一個寫入者；寫入失敗時釋放。單次上傳租約為 10 分鐘，分段上傳每收到一段延長 1 天；過期後由維護 worker 釋放，或由同意圖請求接手。每次接受／接手建立新的寫入者識別；發布來源前鎖住保留並核對識別與租約，遲到的舊請求不能發布或釋放接手者的保留。分段續期也須核對，保留已清除時須從第一段重新上傳。
- Podcast 音訊：每集保留到該集音訊寫入或整份節目刪除。講稿／音訊失敗仍保留，接續生成不再核對這份已接受工作的額度。
- Podcast 影片：只對真正排入佇列的工作保留；同來源的 cancelled 影片只呼叫 prepare 不會重新保留。影片寫入、失敗、中斷或取消時，在同一交易刪除保留；再次生成須重新核對額度。刪除節目也會刪除保留。

會新增檔案的入口在帳號層級的 PostgreSQL advisory lock 內以短交易完成「再次辨識冪等 key＋核對額度＋建立保留」，檔案落盤在鎖外：上傳教材以「已用＋本次大小 > 上限」判斷；分段上傳在第一段以「已用＋宣告大小」判斷；加入 YouTube 在空間已滿時拒絕（參照很小，不另保留）；建立 Podcast 以「已用＋集數 ×（音訊估值＋勾選影片時的影片估值）」判斷；生成、重試或補建影片以「已用＋待保留集數 × 影片估值」判斷（已有保留的分集不重複計）。上傳保留綁定入口（普通／分段）、帳號、教材、Idempotency-Key 及請求意圖（檔名、媒體類型、宣告大小；單次上傳另含內容雜湊）。不同入口的同 key 會重新核對額度；普通上傳同 key 不同意圖依既有冪等規則回 `IDEMPOTENCY_CONFLICT`；同意圖已完成的重送回傳原結果，不因額滿失敗，普通上傳進行中的並行重送回可重試的 `STORAGE_BUSY`（HTTP 503），不另行寫入。分段請求由檔案鎖依序處理，第一段代表重新宣告。分段重開先核准新宣告，再移除舊分段與 metadata；拒絕時保留舊狀態，不刪除作為檔案鎖的 metadata，以免影響另一個已接受或等鎖的請求；初次拒絕留下的空檔沿用一天後的暫存清理。接受前先核對教材權限與狀態；同時需要帳號鎖與教材鎖的交易一律先取帳號鎖，再取教材鎖（包含外鍵需要的鎖），只有教材鎖的背景成品寫入／刪除不取帳號鎖。超過上限回 `STORAGE_QUOTA_EXCEEDED`（HTTP 409），回應附 `storage.used_bytes／limit_bytes`；帳號鎖等待超過 5 秒回可重試的 `STORAGE_BUSY`（HTTP 503）。已有內容照常閱讀、播放、匯出與刪除。卡組匯出暫存由維護程序清除、Podcast MP3／Markdown 匯出在記憶體產生，不計入。`GET /v1/account/storage`（`account-storage/v2`）回傳已用（含保留）、保留、上限、剩餘、五類細項與依用量排序的前 5 大教材，顯示於全站頁首經驗條右邊：大於 1280px 為儲存圖示、細進度條與已用／上限；1280px 以下為圖示與整數百分比（已用大於零但不足 1% 顯示「<1%」）。點按展開已用、上限、剩餘與預留說明、分類分色堆疊條及各類大小，並可從前 5 大教材清單進入教材；細項合計等於已用，預留不重複加總。空間已滿以警示色與警告文字呈現。教材工作區不顯示。

## 圖片、音訊、影片與 YouTube

圖片組在瀏覽器依目前順序打包成不壓縮的 ZIP（`0001.png`、`0002.jpg`…），原檔即此壓縮檔。沙箱以 PyMuPDF／PyAV 將每張圖排成一頁（長邊 842 pt，JPEG 依 EXIF 轉正），mapping 記錄 `image_number`；之後與掃描 PDF 相同，由 Unlimited-OCR 建立 Evidence。嵌入 PDF 的一律是壓縮影像：不超過 1.5 MiB 且長邊不超過 2,500 px 的 JPEG 原樣嵌入，其餘縮到長邊 2,500 px（OCR 繪製約 2,340 px 已足夠）後以 PNG 或 JPEG 嵌入；50 張 1,200 萬畫素手機照片（合計 88 MiB）轉成約 30 MB 的 PDF。HEIC 不支援：PyAV 無法組合 iPhone 照片常用的圖塊格式。

音訊、影片音軌與沒有可用字幕的 YouTube 在斷網沙箱轉成 16 kHz 單聲道 Opus，再送到主機 Podcast provider 的 `/media-transcribe`，由本機 faster-whisper large-v3-turbo 以顯示卡批次辨識（語言自動偵測），不外送。辨識與 CosyVoice 共用 provider 的 GPU 鎖；每條教材 worker 內依序執行 OCR 與轉檔；設定多條 worker 時，不同教材的工作可重疊，顯示卡辨識仍由 provider 的 GPU 鎖控制。實測 1 小時中文課程：CPU int8 約 12.7 分鐘，顯示卡約 1 分鐘。

YouTube 連結以 yt-dlp 讀取：只接受單支影片（Shorts 照常；帶清單參數的影片網址只取該影片），拒絕播放清單、直播或尚未播出、會員限定、私人與年齡限制影片，以及超過 2 小時的影片，並回報具體原因。只用上傳者字幕，順序為繁體中文 → 簡體中文 → 影片原語言；YouTube 自動字幕不用，改暫存音軌以本機辨識，辨識後立即刪除。影片的原檔是 `youtube-source/v1` 參照（影片 ID、標題、頻道、長度），不保存影音。使用 yt-dlp 有服務條款灰色地帶，YouTube 改版時需更新 yt-dlp；版本記在轉檔政策。

逐字稿依每句開始時間歸入 2 分鐘時間段，一段一頁（沒有語音的時間段不成頁），單頁放不下時縮小字級而不換頁；辨識片段併成約 180 字的段落，原文不改寫。mapping 的 `origin_locator` 為 `start_seconds`／`end_seconds`，`media` 記錄辨識來源（`whisper` 或 `uploader_subtitles`）與語言。Evidence 仍是 1-based 頁碼與區塊，下游（OCR、索引、問答、Podcast、筆記、題組）照常使用；來源回查顯示時間範圍，音訊由 `/v1/artifacts/{id}/media`（支援 Range）從該段開頭播放，YouTube 由 `youtube-nocookie.com` 內嵌播放器從該秒播放。來源清單以實際時長呈現，原文定位使用已核對的時間範圍，不以內部頁數當成影片頁數。

媒體轉換政策為 `normalization-policy/v1` 的 `kind: media`（另記 yt-dlp 版本），文件轉檔政策不變。轉換沿用來源正規化的 lease 與取消：辨識等待期間持續續租，取消或刪除教材會中斷 provider 請求。辨識服務不可用或失敗時如實標為失敗（`STT_PROVIDER_UNAVAILABLE`／`STT_FAILED`），可按「重試轉換」。

## 草稿與來源快照

建立草稿後，各檔案以獨立 Idempotency-Key 上傳並排入轉換。使用者確認就緒來源與順序，後端同交易封存 SourceSet、bundle manifest 與 processing run；之後上傳的檔案不混入已建立工作。

相同意圖重播不重複建立；輸入、順序或 base revision 不同則拒絕衝突。未被使用的來源可移除；只被 failed／cancelled 工作引用的來源可退出清單，內部保留原檔與封存關係。正在處理或已發布結果使用的來源受保護。重新上傳使用新的意圖，已移除 normalization 不能用於新分析。

## 按需求選段

使用者仍選取來源檔案；補充學習與主題建立由後端決定分析範圍。研究核對通過的完整段落保存原文，下載時核對內容版本，正規化時定位到原 PDF 的頁碼與區域並補入同頁鄰接區塊。`material_sources.analysis_scope` 保存不可變的選讀意圖，`source_normalizations.analysis_scope` 保存實際定位結果；兩者不能冒用不同來源。

完整 PDF 仍可預覽與下載，但教材分析僅對選定頁面與區塊執行 Evidence／OCR、語意擷取及檢核。選讀範圍不同於全文驗收；引用始終回到原文件頁碼。原文定位不到、來源變更或範圍不合法時明確失敗，不以全文分析兜底。直接上傳的教材維持全文範圍。

選材保留必要前提、新條件、反例與獨立證據；不確定是否新增時，不以不穩定的舊概念名稱硬性淘汰。原始需求及確認範圍是驗收依據，不由生成後的概念表重新定義要求。

## Evidence 與分析

PDF 原生文字足夠時建立 native Evidence；重要圖片區域使用 Unlimited-OCR。混合頁保留原生文字並補入 OCR 結果，未恢復內容留下複核提示。

原生文字的編號章節標題即使位於頁底，也依字級辨認，讓下一頁正文接回正確章節；沒有章節編號的頁尾仍沿用位置限制。教材審查比對章節主題時可忽略數字編號，避免把已有章節的學習概念當成版面資訊移除；原標題、Evidence與已保存版本不改寫。

Evidence 保留教材、1-based 頁碼、區塊、定位及技術字面值。換行合併依幾何與段落結構，不跨欄猜讀序。

新工作採 `independent-evidence-blocks/v1`：每批以約 4,096 個新來源 tokens 為目標，最多八批同時推論。每批只讀自己的來源，模型用局部陣列索引描述子圖，全域概念身分由請求內容與局部索引的 hash 產生；不重送累積概念目錄。Gemma 使用服務 tokenizer，Luna 使用本機 tokenizer 估算；完整請求仍保留輸出預算與包裝餘裕。單一來源區塊不截斷。

各批原始回應先保存，再核對來源引用與關係；通過後保存可接續的子圖。單一協調者合併結果，不讓多個執行緒共同改概念狀態。Checkpoint 同時保存連續游標及已完成但前方仍有缺口的範圍，畫面計入所有已保存的完成量；失敗接續會跳過已合併範圍，並重用已完成但尚未寫入 checkpoint 的子圖。來源、模型、請求與檔案 hash 不符時拒絕重用。

新概念不覆蓋舊概念，跨批次同義名稱允許分開保存；這個階段不額外呼叫模型做全域去重或推測跨塊關係。來源頁碼、區塊及字面值仍按原規則核對。檢核與發布維持既有保護，`needs_review` 不視為內容已驗收。

新分析採 `traditional-chinese-literals/v1`：概念名稱、重點與關係理由使用繁體中文，必要的原文名稱及縮寫保留為別名；Evidence、原始檔與頁碼維持原文。一般英文括注與連字號不當成整段不可改寫的程式碼，數值、單位、程式片段與公式則由共用檢查核對。一般來源的新重點以 `localized_meaning_v2` 記錄投影，數量與單位須以完整 token 保留；已發布的 `localized_meaning` 與 `semantic_meaning` 沿用原驗證規則，不重寫既有內容或雜湊。

音訊／影片／YouTube 的新分析使用 `material-block-request/v2`／`material-block-response/v2` 與 `source-excerpts/v1`：從已驗證的時間映射傳遞字幕／ASR 類型，按獨立主張切分、移除口頭贅詞與純導覽旁白。Claim 保存可唯一逐字定位的原文節錄，起訖限原文邊緣或句／子句標點（半形標點須後接空白或原文結尾，不從 `10:30`、`v1.2.3` 中間切開）；無標點逐字稿保守引用整段，不以空白裁掉前文限定。每段口語引用至少 4 個非空白、非標點字元，整段引用也適用，單字或標點不能充數；依每個引用的實際來源檢查，混合引用中的 PDF 完整區塊不套口語長度門檻。以 `spoken_excerpt_meaning/v1` 保護節錄內的完整技術字面值；字面值不符時只還原該節錄（`spoken_excerpt_literal_repair/v1`）。引用未通過逐字或邊界核對時，每次候選僅對失敗引用請它重選一次；不改主張，不以模糊比對修字，仍不符就拒收並保留待核對狀態。完整 Evidence、來源、頁碼／區塊與時間映射仍保留，翻譯、審查及概念整理不把短引用擴回整段。疑似 ASR／字幕錯字保留原文，不猜正字；審查沿 `uncertain`／`needs_review` 標待核對；若候選已擅改疑詞或數量關係，只允許撤回成該主張完整的逐字節錄並註明待核對，不接受猜測訂正。保護以 Claim 為單位：只有全部引用皆為 transcript 的主張套用口語疑字規則；同概念中的 PDF Claim，或同一 Claim 混合 PDF 與逐字稿，維持一般規則。去重不得改寫或合併受保護 Claim，但仍整理同概念其餘主張。政策只套新分析，既有教材與 hash 不變；重分析及原音複核另案。

若初次結果仍是外文敘述，或因字面值不符而退回來源，僅對需要修正的文字分批翻譯。技術片段先以位置代號保護，回覆必須逐個保留代號，還原後再核對原始來源；修正失敗不能默默以整段外文發布。每次真實請求與回應分別保存、計入語意呼叫，完整通過的子圖才可供接續重用；後續教材審查仍核對事實、條件與關係。引用書目清單本身不建立教學概念，不從論文標題推測正文未提供的知識。概念卡新設計同樣使用繁體中文說明；既有產物不自動重製。

審查修正也會檢查混入中文敘述中的外語詞；局部修字時保護其餘文字與公式。Claim 修正以套用後實際保留的「原引用＋模型選取引用」核對支持，避免誤判原有公式沒有來源；審查紀錄仍分別保留模型真正選取的引用，不把原引用冒稱為新增選取。

舊 `contiguous-evidence-new-input/v1` 的 run 與 hash 原樣保留；本次已知 v1 → 獨立子圖策略允許在新的 retry 工作中沿用已保存的 Evidence、概念與游標，只處理剩餘來源。不允許反向降級或藉此換模型／任意改提示。provider 的教材語意請求使用八個槽位，其他文字功能保留原串行鎖；GPU 服務端仍有自己的實際併行上限。

分批容量探測從 8 個 Evidence 起逐倍擴大，遇到上限後縮小搜尋範圍，避免每批先把所有剩餘教材送到 tokenizer。最後仍核對實際請求容量、保留輸出空間，並盡量沿章節邊界切分；單一 Evidence 不截斷，放不下時如實失敗。

單一尚未被 Claim／Relation 引用的 OCR 區塊超過輸入額度時，可從原 PDF 的同一區域裁切後重辨識一次。新文字建立新的 Evidence ID，保留原頁、區域與閱讀順序；新工作保存重辨識紀錄及 checkpoint，原失敗工作不改寫。仍放不下、已被引用、原文非 OCR 或儲存失敗時如實停止。OCR 次數包含這次區域重辨識，因此可能大於頁數。現行 OCR 防重複窗口為 256，並拒絕未正常 EOS 結束的生成；這是執行恢復機制，並非內容品質驗收。

字面值保護須容許 PDF 行內程式碼換行及合法欄位存取，不能將技術識別字誤當未翻譯散文。翻譯補正只重試失敗項目，已通過項目不重送；來源、數值與結構契約仍須通過。

## 暫時 Luna 並行測試

`STUDYDY_LUNA_PARALLEL_TEST` 預設為 `0`。明確設為 `1` 且使用 Luna 時，審查協調者最多同時處理兩批；各批獨立驗證與保存，失敗後停止派送並收完在途結果，成功批次可重用，最後依原概念順序合併。容量超限仍分段並保留完整來源；取消會傳至所有在途模型工作。

主機 provider 同時設為 `1` 時，來源分析與審查共用兩個背景槽位，其他文字功能共用原本的一個槽位，該 provider 的文字推論最多三路。題組準備使用獨立 worker，避免等待整份教材；另一份教材仍沿用教材工作佇列。這不是帳號全域額度保證，其他 Codex 程序不受此 provider 的槽位管理。Gemma 不啟用此排程例外。

測試結束時，在 backend 環境及主機 provider 都設回 `0`，於安全空檔重啟即可恢復原排程；不要改 runtime lock 或清除已保存批次。正式部署的暫時 provider 設定位於 `~/.config/systemd/user/studydy-podcast.service.d/temporary-parallel.conf`。

## 檢核與發布

初次分析與追加結果都經教材檢核。模型提出整合、案例歸屬、別名、文字及關係修正；程式核對覆蓋、來源、先備關係與字面值。覆蓋／歸屬錯誤可有界補正，無來源支持的修改保留原文或拒絕發布。

模型的概念審查回覆以每個輸入編號作為必填欄位，避免陣列中重複同一編號而漏掉其他概念。程式按明確欄位還原概念身分，再檢查完整覆蓋與來源支持；不按回覆順序重新編號。原始回覆與還原後提案分別保存在私人分析紀錄。

檢核請求超過容量時，分開待檢核概念，完整來源脈絡在各組保留；若單一概念仍超額，先保留該概念全部 Claims、引用及其所在頁面的完整區塊，排除原大批次中其他頁面的附帶脈絡；不同來源的同頁碼不混用。這個範圍仍放不下才明確停止，不截斷原文。原範圍已有有效回應時優先重用，不重新分批或推論已完成項目。已驗證批次可重用。編輯編號限於本組提供的 handle，同類編輯中同一 handle 最多一筆；越界或重複時回饋具體編號，最多補正一次，再次失敗仍拒絕，不任意挑選一筆套用。

別名移除須逐字符合該概念的既有 aliases，包含大小寫；不得以概念名稱取代別名。不合法提案回饋原別名、未知或重複的移除值及來源歸屬，沿用同一批次最多一次補正額度。明確接續時優先檢查最新補正稿，針對仍存在的問題補正，有效批次不重跑；補正仍不合法就停止，不由程式折疊大小寫或猜測刪除目標。

每筆別名修改都須由模型明確選出該概念的一個支持來源，也可另列補充引用。程式保存並核對模型的選擇，不替缺漏提案填入任意既有來源；資料不足時應省略修改。

概念審查亦由模型在每個概念欄位的 `concept_source` 明確選取自身支持來源，再於 `decision` 填寫審查決定及額外引用。來源不足以支持改動時保留概念或標記待確認；後端仍核對概念身分與來源歸屬，不自動補來源。

單批審查的格式、概念覆蓋、來源引用、歸屬、循環、分類理由及各類編輯契約錯誤，共用最多一次補正額度，不為每一種錯誤增加新一輪重試。輸出 schema 同時約束動作、target 與 metadata 理由；作者／版面／格值以外不能僅換理由代碼而排除內容。來源版本變更、跨批合併與發布故障不屬於這個模型補正範圍。失敗頁顯示具體中文原因、錯誤碼及最後保存進度，補正失敗不冒充完成。

不同概念可能共用同一 canonical Claim。跨段提出相同改寫時合併來源與理由；改寫互相衝突時不套用任一份，保留原文並記錄待審查項目。一般檢核的 `group`／`example` 只提出教學分組，不代表概念等義，也不直接合併 canonical 節點；先備關係仍保護其兩端。

檢核之後依 `source-preserving-consolidation/v1` 整理跨批次、跨來源的等義概念，並處理同一概念內重複 Claim、重疊句段與雙語翻譯後的重複。全圖短目錄只用來找候選，同名或同別名的節點亦列入比較；實際合併須讀完整 Claims 與原引用，不能只因名稱相同或內容相關就合併。每筆原概念及 Claim 必須有唯一去向，來源完整聯集；以原文為底稿，只刪除等義重複，其餘數字、公式、條件、例外與研究歸屬保留，不重新摘要或搬移不同概念的事實。改寫與獨立語意覆核分開呼叫，未改的內容亦檢查是否漏掉重複；每批最多產生四份新稿，供語意與字面值分別補正；重複相同失敗立即停止，仍失敗保留原內容並標記待檢核。接續時可重用舊稿及精確拒絕理由，重播不消耗新稿額度，也不冒充通過。

覆核同時檢查節點內與節點間是否仍有等義重複；原本沒有重複也算通過，不以是否刪字判斷成功。同一機制的概述、條件與執行細節可合併並保留各自補充，不能只因 Claims 詳略不同就當成不同概念；核心定義、操作或學習問題不同才分開。「合併成員是否等義」只適用於實際合併多個原節點的提案。此階段檢查去重有無新增錯誤、改換事實歸屬或遺失資訊，不要求順便修正舊 Claim 原有的語意／事實問題。

整批補正仍不合格時，按完整候選等義群縮小批次再處理，避免長內容補正時遺漏其他項目。候選群不拆散，仍逐項執行相同的語意、字面值與來源驗證；單一候選群仍不合格才保留原內容並記錄待檢核。縮小批次會增加檢核總批數，已完成量不倒退。

合併後重算概念／Claim／Relation 身分、章節與學習路徑；同義節點之間的邊另存為內部關係，其他關係重新接到合併節點並保留來源。方向衝突、必要先備循環或來源驗證失敗不能套用。提案、覆核與新舊對照保存在私人分析紀錄，原版與原 Evidence 不改寫；`needs_review` 仍不代表品質已驗收。

有可用新增內容的 partial／needs_review 結果可發布；無可用新增內容、取消或失敗時保留目前 head。一般產品介面沒有重新分析或只重新檢核目前版本的入口；學生產生新版本須在教材來源頁新增來源後更新地圖（或由補充學習追加來源）。新版發布後，舊版卡組與學習由學生在教材頁按「移到新版」承接（見[學習與評量](learning.md#移到新版卡組與學習進度)）。

Demo 的 POST-03 修復另有[指定教材一次性維護指令](deployment.md#指定教材的一次性重分析)，只能在合併部署後執行。它使用原來源建立全量分析工作，保留原版本與學習紀錄；分析、審查、合併、新版章節及首次自動摘要共用最多 300 次 Luna 請求，重啟、失敗與首次摘要重試不重設額度。首次摘要完成後的手動重生及完整筆記不屬於這次維護。此維護模式沒有公開 API，不改一般新增來源流程。 使用者另行授權的指定失敗 run 可透過部署後的 `--resume-once` 恢復一次，沿用原額度與已驗證快取；重複恢復或再次失敗不得重設額度再排。

## 文字筆記

教材的「筆記」分頁提供重點整理與完整筆記，依已發布版本的學習順序、重點與 Evidence 生成；每一節列出來源頁碼，可開啟原文或跳到對應概念地圖。兩種筆記使用同一套結構（`material-notes/v12`），差別只在內容量：開頭是程式依各節標題與層級產生的章節大綱（不另請模型撰寫），章節（level 1，編號「一、」）之下接小節（level 2，編號「1.1」）；每節由條列（最多三層巢狀）、必要的短文字、多個表格（可有表格標題）、LaTeX 公式與醒目區塊組成。醒目區塊只有案例研究、討論問題、重要提醒與重要教訓四種，只在原文本身有對應的案例、問題、提醒或教訓時使用；不加 emoji，也不寫結尾的學習目標總結。正文不可直接編輯。v11 以前的段落格式（標題、正文、單一表格與純文字公式）在重新生成前仍可閱讀與匯出，不轉換也不補大綱。教材原有的待核對／未完整處理提示仍顯示，不因筆記生成成功而宣稱教材已驗收。

重點整理在教材版本發布後自動排入教材執行緒；完整筆記只在學生按下生成時排入。兩種筆記分別保存與快取，瀏覽不觸發生成。

完整筆記依目前地圖區域／章節分區生成，區內再按完整重點切批，不設總呼叫上限。畫面顯示已完成分區與批次，已通過來源與內容核對的批次會保存；契約相同時，中斷或失敗重試只接續未完成部分，不重新呼叫已完成批次。若寫作／核對契約、模型身分或生成設定已改，重試會清除舊的未發布分區暫存，以目前契約重新開始；不混用舊批次，既有筆記與註記保留。

所有批次通過後，若存在二級小節，再依整份標題、概念與來源檢查章節歸屬；只可將錯掛的二級小節提升為章節，不改正文、標題、來源、順序或既有一級章節。格式錯誤補正一次後仍失敗就不發布；已通過批次保留，相同契約續接只重做這個整理階段。章節編號與大綱仍由程式產生。

兩種筆記的批次都適用：單一重點連同同頁補充原文就超過一批的容量（完整筆記為 12000 token，重點整理為該工作的模型上下文預算）時，只對這個重點省略一般同頁補充原文，獨立規範詞與重點自己的 Evidence 完整保留，並以 `context_omitted` 記入診斷；省略後仍過大就以 NOTE_INPUT_TOO_LARGE 失敗。某一批因格式、引用或內容核對（含概念補寫）被擋下而失敗時，同一工作內只重寫這一批，最多共三次嘗試，核對標準不變，已通過的批次不重跑；契約、容量與 provider 錯誤等重試不會改變的失敗不重試。有重試或三次都失敗的批次以 `part_attempts` 記下嘗試次數與每次的錯誤碼（只試一次就通過的批次不另記）；三次都失敗時整份不發布、標示失敗。

完整筆記發布前須涵蓋該版本全部重點，所有段落須引用原重點的合法 Evidence；必要表頭、規範詞或條件可補取同一原檔、同一頁已保存的 Evidence，使用時須列為該段正式引用。補充原文與原 Claim 節錄分開；同一 Evidence 的其他原文部分也可補入，不修改已發布知識結構；不能只引用表頭取代重點原文。原頁沒有表頭就明示缺口，不推測欄名。

逐段核對另外收到本節重點可用範圍內、同檔同頁但尚未引用的 `reference_context`，只用於發現漏引的必要表頭、規範詞與限制，不能直接支持候選。確認缺漏須先拒絕並在 `missing_evidence` 回覆本次補充原文的 X ref，程式按精確 ref 補入合法正式引用、驗證後重核整段內容與涵蓋，不改正文，也不靠理由文字的區塊號猜來源；仍有內容錯誤才局部重寫，不把其他檔案或其他頁的內容配入。局部重寫由程式保留原章節層級，避免修文改變主題歸屬。

合法引用之後，仍會逐段用模型對照該段引用的原文，在同一次請求分別回覆內容正確性與實質涵蓋：前者逐一核對標題與每個位置：每個條列項（含巢狀子項）、文字、表格標題、表頭、每列表格、公式，以及醒目區塊的類型標籤與標題（區塊類型須有原文依據）；位置名稱如 `blocks.0.item.1.0`、`blocks.2.row.3`、`blocks.1.formula`、`blocks.3.callout`，與局部修正共用。後者核對各個列入重點是否實際說明。涵蓋回應須指出真正有解說的筆記位置（條列項、文字、公式或表格列；表頭、表格標題與區塊標籤只能搭配），位置必須存在於當前或同重點已核對段落，不能拿來源編號充數；也不能要求筆記補寫重點文字中不受原文支持的概括。同一重點可跨段整理，在最後出現的段落合併已核對前文判斷，不要求每段重複解說；完整筆記須保留核心結論與必要條件；重點整理只要重點的核心主張或結論有實際說明就算解說，其餘細節、個別數值與範例可留給完整筆記，但不能只列名稱或重點 ID。重點文字不是事實來源，原文的適用範圍與規範強度優先。

公式以單行 LaTeX 保存，只接受網頁（KaTeX）與匯出（matplotlib mathtext）都能排版的指令子集；含未支援指令、未跳脫的 `%`／`$`／`&`／`#`、控制字元、未分組的多字元上下標或無法解析時，以 NOTE_FORMULA_INVALID 視為格式錯誤：先帶該公式與原因補正一次，仍不符則依批次重試。範數的 `\lVert`／`\rVert` 在匯出解析與排版前等價轉為雙豎線 `\|`，不改保存的 LaTeX；不能拿關係符號 `\mid` 當作 `\left`／`\right` 的定界符。筆記校驗與匯出共用排版鎖，避免 mathtext 的全域狀態在多執行緒間互相干擾。公式中的每個數字（上下標與全形數字視同一般數字）都須逐字出現在該節引用的原文，否則不呼叫模型直接列為該公式位置不符，走局部重寫；變數、符號與分式結構由逐段核對比對原文。寫作請求帶入前文最後的章節標題，只供模型決定本批開頭延續為小節或另開章節。

寫作與核對均保留原檔／頁碼、區塊順序與位置以讀取原有表格對應；新增邊界、數值／標籤錯配、條件、單位與否定不符都不得發布。事實核對不符會帶理由重生不符段落並核對替換內容，其他已核對段落保留不動；完整筆記仍不符則工作失敗，保留上一份筆記；重點整理則刪掉這一段，其他段落照常發布。核對回應遺漏位置、格式錯誤或服務失敗也不發布，不把引用 ID 或 HTTP 成功當成內容正確。

重點整理只引用正文真的有解說的重點。核對指出某重點未解說時，程式直接移除該重點在全稿的所有引用及只屬於它的來源，不請模型整稿重寫；引用有變動的段落重新做事實核對，請求完全相同的段落沿用已核對結果。段落沒有剩下重點就刪除。刪 ID 不能掩蓋事實錯誤：同段另有事實問題時，先移除 ID 再重核，仍不符就照上段局部重寫一次，再不符就刪段。完整筆記仍須涵蓋全部重點，不適用這個摘要取捨。

重點整理不設頁數上限，長度隨教材的概念數自然變化：知識結構中的每個概念都要寫到，每個概念只說明最核心的重點，細節留給完整筆記。一次寫作請求放得下全部重點與原文時，直接交給寫作挑每個概念的核心；放不下時先以概念為單位挑選：挑選請求只帶概念名稱、重點文字與來源檔名，不計原文與同頁補充原文，依該工作保存的模型上下文預算分批，每個重點只送進一次挑選（與前面概念共用的重點只在第一個所屬概念列出）。只有一個候選重點的概念不呼叫模型直接選入；概念的候選都已在前面概念列出、且都沒被選中時，取它的第一個重點。挑選回應須逐一回覆每個概念、只選該概念自己的候選，不符補正一次，仍不符以 NOTE_SELECTION_INVALID 失敗。寫作帶入選中重點的完整原文，不截斷 Evidence；一次放不下時沿用完整筆記的切批方式（依同一預算按完整重點切批），計畫與已核對的批次隨工作保存，相同契約重試只接續未完成的批次。

重點整理的「涵蓋」以概念判定：每個概念至少要有一個重點留在核對通過的段落中，也就是至少一個核心重點被實質解說。逐段核對、移除未解說重點與刪段之後，若某概念完全沒有被解說，只為這些概念局部補寫一次並依學習順序插回，新段落比照局部重寫核對（仍不符直接刪段）；仍有概念沒被解說，這一批就以 NOTE_COVERAGE_INCOMPLETE 失敗並依上述批次重試；三次都失敗才不發布，保留上一份筆記。每份新稿與局部修正回應的一般格式錯誤可補正一次；模型 schema 驗證仍失敗時統一回報 NOTE_FORMAT_INVALID，交給上述三輪批次重試，並記錄 part_attempts。公式語法錯誤只送出錯的 LaTeX 與該小節引用原文，不重送整批教材或前稿；每個公式位置最多補正一次，程式只替換公式，仍須通過語法驗證及逐元素原文核對。完整筆記的重點與來源配對錯誤（包含局部修正回應）每個出錯段落各可補正一次：配對補正會列出缺漏／多列的編號與可用來源，程式只採用出錯段落的新編號，保留正文及其他段落；補正回應缺少目標段落時回報 NOTE_FORMAT_INVALID。重點整理的配對由程式整理：未知或重複的重點／來源編號直接丟掉（不再走格式補正），重點沒引用自己的來源就移除該重點，未知或不屬於本段重點的來源就移除該來源，之後交給事實核對抓出失去來源支持的文字。發布前刪掉的重點與段落、補寫的概念，以及失敗原因，只以錯誤碼、重點／概念編號、段落位置與核對理由的 SHA-256 摘要碼保存在 `material_notes.generation_diagnostics`，並以同一份 JSON 記入後端日誌（`NOTE_GENERATION_ADJUSTED`／`NOTE_GENERATION_FAILED`），不記教材或理由全文；欄位只反映最近一次發布或失敗（沒有刪減的成功為 NULL），重新生成時覆寫，API 不回傳。筆記若中途因停止或租約恢復接續，只記最後一段執行的事件。網頁可自然捲動，不縮字或裁掉內容。

筆記可匯出 PDF、Markdown 與 Word（.docx），保留章節大綱與編號、層級標題、巢狀條列、全部表格、公式、醒目區塊、來源檔名／頁碼／區塊及個人註記。Markdown 開頭提供可點擊目錄與穩定的中文標題 anchor，公式原樣寫成 `$$…$$`；PDF 與 Word 以 matplotlib mathtext 排成 300 dpi 圖片（中文用 Noto Sans CJK TC），PDF 與 Word 的長公式依可用頁寬等比例縮放，Word 的替代文字保留 LaTeX 原式，公式在 Word 中不是可編輯的方程式物件。無法對應目前段落的註記連同原版本與段落快照匯出。PDF 使用章節目錄、層級標題與完整正文，來源編號對應同頁頁尾註腳，個人註記緊接所屬段落；兩種筆記都依內容自然分頁、標題使用中文粗體字型，標題與正文開頭同頁，長段落與條列照常跨頁；匯出只讀取已發布內容，重生中或失敗時仍可匯出上一份筆記。筆記畫面沿用舊稿時，註記與匯出綁定實際內容的 content_revision；註記的 expected_generation 使用 content_generation，避免把舊段落寫到新內容。尚無已發布內容時不提供匯出。Word 匯出會移除 XML 不允許的控制字元，保留 tab 與換行，作者標為 Studydy；原筆記不變。

每段可新增、編輯或刪除自己的個人註記。註記保存原段落快照；重新生成或教材更新後，只在來源位置／節錄與重點內容完全相同、且唯一對應新段落時掛回。無法對應的註記列於「先前段落的註記」，可展開當時段落及來源，內容不遺失。註記引用的教材版本保留供查來源。新筆記完成前或生成失敗時，仍可閱讀上一份已發布筆記與註記。

## 概念難度

概念難度在讀取時由已發布教材版本的先備關係與重點數計算，不改寫教材、Evidence 或作答。先備鏈至少 3 層（根為 0，只計 prerequisite）或至少 5 個重點時，顯示「預估偏難」及實際結構原因；回傳所有概念，未作答也可查看。個人的「你的難點」另依真實作答判定，規則見[學習與評量](learning.md#學習診斷與概念難度)。

## 追加與接續

設有學習目標的教材發布新版時，保留目標日期與比例，依新版可檢測重點及可承接的真實作答重新排期。目標區顯示前次已看版本與新版的重點數變化；關閉提示不變更學習紀錄或目標基準。概念級完成承接若缺少逐重點證據，不補造成目標完成點數，另提供手動複習入口。

新來源將確認過的學習範圍封存至 bundle，分析與檢核沿用該範圍；不追改已發布 bundle 的 hash。

追加只分析新增來源，再整合檢核；發布同交易更新知識結構、run 與教材 head。我的教材開目前 head，學習依 exact revision 恢復。被學習、活動工作或未刪除研究的 base revision 引用的結構保留，其餘完整結構可清理；來源檔跨版本重用。

每頁成功整理後，先原子寫入頁面 Evidence checkpoint，再更新處理頁數；快照綁定 owner、教材、來源集合、原來源頁碼與 runtime，保留完整原文及 Evidence 身分。失敗或中斷後，只重用來源與分析設定相容的已保存頁面，不重新渲染或呼叫 OCR；不相容的舊工作略過、由新 run 重新擷取，尚未成功擷取的頁面仍需重試。

章節導覽名稱超過 512 字元時使用首行或帶省略符號的顯示標籤，完整標題原文仍保存在 Evidence，不截斷來源或改寫其 ID。章節建構失敗回報 `DOCUMENT_EVIDENCE_INVALID`，已保存頁面仍可接續。

語意階段 checkpoint 保存累積狀態、游標及執行快照。接續批次依來源頁序重建，不受 JSON 欄位順序影響。相同 owner、教材、輸入與分析設定的重試可重用已完成批次；只剩確定性建構／發布時不再推論。新 run 會略過輸入／分析契約不相容、或封存 runtime 無法與 binding 核對的舊工作，從頭分析；不讀取、不修改或刪除被略過的舊 checkpoint 與封存。相容性檢查通過後，若快照內容未通過完整性核對，仍停止而不靜默重跑。

私人 analysis archive 保存請求與回應；重用和新增呼叫分開計數。Checkpoint 只在 DB 確認發布後清理目前 run 與同輸入且相容的舊 run；不相容舊封存保留。清理失敗由 worker 補做，過期 worker 不能重建已結束工作的狀態。

## 取消與刪除

取消更新保留已發布地圖與學習；刪除整份教材則先保存意圖、阻止新工作及過期發布，再清理來源、分析與學習資料。檔案先進 quarantine，DB 回滾時還原、提交後刪除，清理可重試且不影響其他教材。

取消不保證外部服務立即停止已送出的計算。教材改名只更新顯示名稱，不改 hash 或學習紀錄。

## 讀取與連線

每個程序依 DSN 重用 SQLAlchemy 連線池，基礎 5 條、臨時最多再加 10 條；交易與 Session 仍按操作建立。鎖等待 5 秒、SQL 60 秒的設定使用 SET LOCAL，交易結束後恢復；借出前檢查連線。隔離測試刪除自己的 DB 前先釋放該 DB 的池。

Podcast 與補充搜尋的唯讀操作使用教材共用鎖，追加、取消及其他修改仍使用排他鎖。搜尋紀錄清單只讀摘要，候選、授權與取得資訊由單筆讀取載入。知識結構讀取仍核對內容、run binding 及來源關係，不掃描原始 PDF，也不以跳過核對或公共快取換取速度。

## 公開來源搜尋與取得

主題建立與補充學習共用持久的背景研究工作。依需求規劃子題與搜尋管道（一般網頁／官方教學、論文或兩者）；取得一個查詢的結果後先核對用途，不先展開全部查詢。摘要／導讀以小批次初篩，正文先在本機按需求找候選區段，再由模型核對。每完成一小批閱讀即檢查需求是否已有正文支持，足夠便停止擴張，不以候選數量或固定百分比當作品質門檻。

主題規劃須涵蓋完整需求，不以固定主題數截斷後段內容。查詢優先尋找可形成教材的開放來源；Python／MDN 專門搜尋只用於明確涉及該技術的查詢。補缺口時先探索已規劃的新方向，其新結果先於舊候選處理。取得正文後若仍不能匯入，保留參考連結與取得紀錄，不再用模型逐段核對；這些來源不算已驗收，也不能補足教材涵蓋度。

缺口檢查的未讀候選線索也按需求排序、依輸入額度分批，必要時接續下一批，不一次帶入全部候選摘要。不能加入教材的參考來源與存取失敗不送到畫面，完整紀錄保留在研究工作中；分批查看線索不算新的正文證據，也不因此觸發無進展停止。

涵蓋判斷直接核對已保存的原文摘錄，依子題與搜尋方向安排閱讀順序。超出單次容量時分批累積涵蓋結果，不永久丟棄排名較後的已核對原文；短標題與相鄰演算法步驟一併安排，可合併多份來源支持同一需求。閱讀摘要、標題與未送入本輪的原文不作為新支持；模型拆題時額外加入的通用規格或完整程式要求，也不能取代使用者原始需求作為驗收門檻。

缺口補讀保留既有引用及已讀範圍，只讀新增範圍；完全相同的正文可跨入口重用閱讀判斷，各自的身分與使用條件仍需核對。沒有新證據的連續檢查會結束本輪並呈現未補足項目，不能冒稱 covered；使用者仍可明確接續。來源未讀或沒有定位到正文時保留為參考，不因不確定而自動全文分析。

`material_research.search_state` 保存規劃、每輪查詢與 cursor、階段、涵蓋情況與站方要求的等待時間；候選保存閱讀位置、來源引用與逐次存取結果。沿用原工作租約與取消機制，重新開啟頁面可接續查看。進度依目前階段的查詢數或來源數計數，不用經過時間推算百分比。研究 API 只回傳畫面使用的欄位：可選或已選來源的基本資料、閱讀判斷與授權取得資訊，以及進度的階段、計數、各觀念涵蓋狀態與結束原因；進行中的說明只在搜尋時送出。初篩、預覽、存取紀錄、搜尋管道、版本與內部計數只留在資料庫。模型依相同正式 provider 設定執行，不新增付費搜尋或 GPU 常駐服務。完成閱讀後移除暫存全文，只保留引用、摘要與內容 hash。

同 DOI、同版本 arXiv 文件或相同 canonical URL 合併，保留既有候選 ID 與已取得來源。標題詞數只安排初步閱讀順序，不作硬性排除門檻；真正推薦依正文與學習目標核對。大量來源的整理分批累積已核對依據，不將所有全文引用塞進單次模型請求。相關但尚不能匯入的來源與偏題來源不列入畫面，紀錄保留在研究工作中。候選以每頁十筆瀏覽，翻閱已整理結果不再推動新研究。研究會自動依缺口補查到沒有新證據為止，不提供手動補查或補查方向；停止後可接續處理，範圍不合適時重新規劃。

論文仍核對全文版本、使用條件與 DOI／標題；同版本的已知公開位置逐一嘗試，不再限制只能試三處。網頁失敗時先查原站公布的全文／feed，再依當次網址與失敗紀錄推導待驗證的公開入口，不為特定網站或教材加特判。入口必須實際取得並核對文章身分，RSS／Atom 找不到指定文章不算成功。403、驗證頁、DNS、連線逾時、HTTP 失敗與限流分開紀錄。單頁 403 不封鎖整個網域，明示 Retry-After 或 429 才暫停同站請求；這類來源仍算待處理，先讀其他候選，到站方指定時間再接續，不當成已完成審閱。選段匯入仍保留完整原檔，經 normalization 定位後只分析必要 Evidence，不將搜尋摘要當正文；已審閱內容如在取得時變更，須重新核對。

選填設定（僅放私密 `.env`，不要提交金鑰）：

- `STUDYDY_OPENALEX_API_KEY`：以 Authorization header 傳送，提高免費額度；跨主機重新導向不轉送金鑰。
- `STUDYDY_SEMANTIC_SCHOLAR_API_KEY`：有 key 才加入 Semantic Scholar 搜尋，單程序請求間隔至少 1.1 秒；仍需明確全文授權。
- `STUDYDY_UNPAYWALL_EMAIL`：有聯絡 email 且已選論文下載失敗時，才向 Unpaywall 查詢同 DOI 的其他全文位置；email 會隨請求送出。未設定時不啟用。

SearXNG 由 Compose 的 `research-search` 提供，只在 application 網路內可達，不公開 port、不使用付費搜尋 API。這台主機目前採用 Yahoo、Wikipedia 與 Wikibooks；Google、Brave、Qwant、DuckDuckGo 的測試曾出現拒絕、限流或驗證碼，未列入正式組合。搜尋範圍由引擎決定，正文取得不限制在固定幾個網站。

值得深入與資訊不足的來源會依背景研究步驟核對正文。使用 Trafilatura 擷取正文、表格與程式碼；長文先依區段線索定位，再分段核對所需內容，概覽不足時擴大到全文，不以固定篇數、比例或輪數決定完成。公開內容可先閱讀與評估；匯入網頁時另核對頁面明示的 CC BY／CC BY-SA／CC0 等現行使用條件，文章中引用的授權不能代替整頁授權。

相同搜尋與公開正文保留有容量上限的短期快取；搜尋至少間隔三秒，同站下載至少間隔兩秒。這是請求節奏，不是品質判定門檻。尊重站方明示的 Retry-After；等待中的單一來源不阻擋現有證據的涵蓋核對，只有仍有缺口且無其他可行工作時才等待重試。不因一般 403 或逾時封鎖同站其他入口。SearXNG 不再設定三頁上限，研究是否接續由目前子題缺口、已查過的結果與服務實際分頁能力決定。

`STUDYDY_SEARXNG_URL` 預設為內部 `http://research-search:8080`；使用者輸入與搜尋結果不能改變內部服務位置。對外取得仍逐次核對 DNS／IP 與重新導向，金鑰不跨主機轉送。研究中的相關性判斷與引用核對不取代既有教材分析及內容驗收。

## 教材處理進度

處理畫面依持久工作的實際階段顯示：等待資源、整理來源、語意分析、檢查／修正知識結構、建立檢索索引、組裝／發布，成功保存後才完成。等待與發布沒有可用工作分母，不顯示百分比；整體流程用第 N／6 階段，不將不同工作單位加權成估計百分比。

畫面只在首次建立的來源整理階段顯示頁數，其餘階段與追加更新顯示實際工作計數換算的百分比，不顯示內部區塊或批次。追加更新列出該次工作的新增來源，另列沿用的既有來源數；首次建立保留全部來源清單。首次建立若失敗且缺少當前階段計數，仍保留已處理的來源頁數；追加更新不套用整份教材頁數。底層語意分析仍計來源區塊，檢核仍計通過的批次。OCR 無損修復、檢核容量拆分或接續去重可能更新該階段的分母，因此本階段百分比可能調整，不代表剩餘時間。模型回應、檢核、組裝及 artifact／DB 保存都通過後才發布；`partial` 仍保留 `needs_review`，不是品質驗收通過。

階段工作計數與 `review` 階段定義於 `0002_sources_and_processing.sql`，未知的工作分母不回填或猜測。前端拒絕更新時間較舊的讀取結果。重新載入、取消、失敗與中斷恢復保留已保存階段與計數；新重試會建立新工作並沿用可驗證 checkpoint，不改寫舊工作。

## 檢索索引與新格式

檢核後、發布前新增「建立教材檢索索引」階段，來源區塊保存可搜尋術語、概念別名、原文字元範圍及 Evidence 定位。與教材版本同一交易保存成功後才顯示完成；不得在第一次問答時才掃全文建索引。 查詢先由 DB 索引取得有界候選，再按詞彙稀有度排序；概念上下文涵蓋後續相關命中，不只補前三筆，送入模型的原文仍受固定額度限制。來源頁數與實際選讀頁數分開顯示。

新格式不保留舊版讀取轉接。舊教材或舊回答無法使用時顯示明確訊息，可從保留的原檔重新建立；不會背景重分析、覆寫舊版本或刪除原檔。

歷史 `material-notes/v10`（含原 `summary_layout`）與 v11 runtime lock 仍可通過結構驗證供教材分析續接，不改寫封存內容或 hash；筆記生成仍嚴格要求現行 v12 契約及其提示，不執行舊版生成。

## 分析暫時失敗與自動接續

一般使用者分析遇到 RESTART_INTERRUPTED、語意服務暫時不可用／逾時、STORAGE_BUSY 或 SOURCE_BUSY 時，沿同一 run 與已保存 checkpoint 自動接續一次。auto_retry_count／auto_retry_reason 存在工作列，程序重啟不重設，第二次失敗才回 failed；排回 queued 時本次執行進度重新建立，已驗證 checkpoint 不刪除。取消、內容核對（REVIEW_*）、一般模型生成失敗、格式／容量錯誤及空間不足不重試。指定一次性維護 run 排除在此規則之外，仍遵守既有「恢復後再失敗不得自動重排」授權。
## 來源與執行摘要的顯示投影

來源清單、教材列表代表來源與 Evidence resolver 共同提供 display_name、source_kind、duration_seconds、image_count、transcript_source 與 transcript_display_name。時長取已核對 mapping；YouTube 名稱只在顯示時去掉 .youtube，單張圖片去掉（圖片）.zip，多張顯示張數。新舊圖片同規則，不改ZIP上傳格式，不猜逐張原名。

run 的 added_sources／existing_source_count 依固定 SourceSet 與 base 分辨新增與沿用來源。發布時把前後概念／關係數存為獨立 display_summary，再執行既有清理；不把顯示欄位寫入來源或結構 hash。舊run仍可從保留資料唯讀推導，缺前版結構時不捏造計數。

公開概念 uncertain 旗標只從同run已驗證審查封存的 issue=uncertain、口語來源與 review／consolidation 明確映射推導；新舊教材都適用。無法精確對應就不標，unchanged 的概念身分可沿base繼承；原canonical結構與 needs_review 狀態不變。

筆記 API 為 material-notes/v3。content_revision／content_generation 指目前真正顯示的舊稿，source_resolver 跟該稿走；請求revision的status／generation／progress描述新稿。新版尚無已發布筆記時，讀取最近較舊的同種類已發布稿；started_at／updated_at／updating供進度顯示。兩種筆記皆提供分區進度，第一批完成前以不確定狀態呈現。既有清理保護兩種筆記各自最近可讀稿的來源，沒有新增清理入口。

補充研究 progress 依已確認觀念提供 topic_progress／completed_topics／total_topics／started_at，只列正文與來源類型均已核對且可用的候選；逐觀念來源數亦採同口徑，不增加模型請求。完成且找到零份仍如實顯示0。

筆記小節的來源標記依原本小節綁定放在末尾，不推測逐句來源；預覽顯示檔名、位置與原文節錄，點擊在右側查看原文。舊段落註記仍使用當時的來源定位。


## 帳號空間細項

GET /v1/account/storage 使用 account-storage/v2，回傳教材原檔與轉換檔、Podcast音訊、Podcast影片、分析資料、處理中保留額度五項；breakdown總和等於used_bytes。largest_materials列最多五份佔用最大的本人教材，含各自分析資料與保留額度。同一次SQL取得檔案／保留／教材名稱，同一次目錄掃描取得分析總量與教材歸屬；不宣稱DB和磁碟為原子快照。無法對應現存教材的分析檔仍計入總量，不提供失效教材連結。

## 作答中問答限制

`PUT /v1/materials/{id}/assessment-presence` 接受 `assessment-presence/v1`、`assessment_set_id`、`active`。與問答文字、錄音、retry 共用必填 UUID header `X-Studydy-Browser-Id`，缺漏或不合法回 `REQUEST_INVALID`。只接受本人同教材已封題、ready/in_progress 的題組；每 20 秒回報延長至 60 秒。限制範圍為帳號＋教材＋瀏覽器，另一瀏覽器可問。活動期間三入口回 409 `ASSESSMENT_IN_PROGRESS`，不排入模型工作；取消與既有回答不受影響。交卷後題組 completed 立即使 presence 失效，離頁停止回報後到期；讀取不續期。這是介面約束，並非裝置驗證。

### Podcast 步驟與部分略過

列表及詳情 generation.steps 按集提供 script／audio／alignment／video；未選影片且無影片工作時不列 video。狀態依真實工作列與 provider 鎖投影，待領取與等待共用鎖為 queued，已取得鎖才 running；無法讀取 provider 時不猜正在配音。分鏡維持 Podcast 全部音訊 ready 才可領取。started_at 與 elapsed_seconds 是實際領取至完成（含等待）的時間，舊資料沒有時間就 null；鎖不保證 FIFO，queue_ahead 維持 null。

講稿重寫後仍無法核對的段落略過，其他已核對段落才送配音；episode.omitted_content 保存原段號、選定 claim_ids 與 source_check_failed，不保存未核對台詞。門檻以本集選定重點去重後計算，超過半數落在略過正文才回 PODCAST_SCRIPT_NEEDS_REVIEW；剛好一半發布。開場、收尾不計入重點門檻，核對失敗仍略過。前端逐字稿與本集重點顯示固定略過提示。

處理頁的完成呈現不直接曝光整份 partial／needs_review 提示；完成頁與筆記提供固定AI／原文對照說明，來源、品質狀態與核對紀錄仍原樣保存。從主題建立在分析中可透過既有DELETE教材操作取消並刪除；此操作清除所屬搜尋結果，主題狀態改為取消並從列表移除，介面確認須明示此範圍。

教材列表每份source_totals彙總未移除來源：document只加已知頁數、image只加已知張數，audio／video／youtube只加已核對mapping時長；任一影音時長未知則media_seconds=null，沒有影音為0。前端null只顯示頁數／張數，不把逐字稿頁數或部分已知時長冒充教材合計。合計重用來源列表同批查詢及source_display結果，不另加SQL或重讀mapping。

來源清單與確認頁以實際來源種類顯示文件頁數、圖片張數及影音時長；影音逐字稿的內部頁數不加入文件合計。教材卡片讀列表提供的來源合計；任一影音時長未知時不顯示總時長，也不估算。次要「查看逐字稿」開啟右側面板，標示已記錄的字幕／語音辨識來源並顯示原逐字稿 PDF；Esc 或關閉後焦點回原按鈕。

教材更新完成頁依該次工作保存的前後結構計數，顯示新增來源數、概念與關係數的變化；不推估缺少的計數。若卡組或學習進度尚在更新前內容，頁首提供次要「更新」入口，沿用既有承接預覽與確認流程；唯一主要操作為「開啟知識地圖」。概念詳情只在該概念有逐字稿疑義旗標時提醒對照原影片，不由整份教材的品質狀態推導。

教材分析若由伺服器自動接續，處理頁會顯示「已自動重試一次」。沿用原本開始時間；完成或失敗後仍保留這項提示。

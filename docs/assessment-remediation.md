# 錯題補強與本輪判定（B5-R）

使用者已接受：單一觀念初篩後，只補強答錯的重點；複習後答對一題新的題目，就算該重點「本次補強通過」。初篩答對者不立即重問，未檢測不算答錯，補強仍錯可稍後處理。本輪完成與長期已掌握分開。

## 使用流程

1. 完成初篩後，查看本輪通過、待補強、未作答與未檢測。原組答對／答錯數保留為歷史，不把補強後的結果回寫原答案。
2. 待補強項目顯示同一 Claim 的教材內容與原始來源。按「已複習此重點」只保存閱讀確認，不增加答案、分數或掌握證據。
3. 將目前已確認複習的錯誤重點一起建立補強題組，題數由該清單決定。已答對的重點、未作答與未出題項目不自動加入。
4. 新題仍需來源支持、唯一答案與重複檢查；只更換措辭的同題可能被拒絕。產生不足或 provider 失敗如實回報，沿用 B5-D 的單項重試與明確部分發布。
5. 補強答對一題，該重點標為本次補強通過；仍答錯則回到待複習。使用者可確認稍後處理並結束本輪，再回來明確複習接續，不自動無限出題。

初篩及補強都沿用現有題組、worker 與 AnswerEvent，沒有第二條模型流程。每組封存後題目不被替換，歷史能回到原初篩與後續補強。前端依最新要求整組一次交卷，全部答案在同一交易保存並一起顯示回饋；交卷前的選取不保存。重新登入、刷新、回應遺失後查回均接續原題組。

## 判定與掌握邊界

| 狀態 | 判定 |
|---|---|
| 本次初篩通過 | 該初篩題已提交且答對 |
| 待補強 | 已提交的初篩／補強題答錯，尚未由新補強題驗證改善 |
| 已確認複習 | 對最新錯答確認讀過教材；只供下一次補強使用 |
| 本次補強通過 | 同一錯誤重點的新補強題已提交且答對 |
| 本輪檢測通過 | 本輪所有實際目標已通過，沒有未作答、排除或生成不足；只描述本次檢測範圍 |
| 本輪結束、仍有待處理 | 使用者明確暫緩尚需補強的項目，或存在未檢測／未作答；不冒充通過 |

一次閱讀確認不會永久解鎖後續所有補強；新錯答或一次補強產生後，需要新的閱讀確認才能另開下一組，失敗題也可直接按原題組的有界重試。所有新出題皆由明確操作觸發。

長期掌握的新跨輪標準尚未定案，本次不新增間隔排程或武斷門檻。既有獨立作答仍依原兩道不同合格正確題及最近獨立作答判定。補強題組的答案在學習投影中標記 `assisted`：計入作答與本次改善，但不補足／恢復獨立掌握證據。原 Assessment／AnswerEvent 的資格、私有答案、正誤與 hashes 均不改寫。未變內容的跨來源版本繼承也保留補強身分。

同一份伺服器投影供地圖、學習頁與歷史使用。結束本輪後可前往下一個觀念，不再因尚未累積兩題正確而立刻重問本輪已通過重點。

## 保存與 API

migration `0012_assessment_remediation.sql` 在既有 `assessment_sets` 增加：

- `diagnostic_set_id`：補強題組指向同 owner／StudySession／KS／Concept 的原初篩，資料庫外鍵與不可變 origin 保護關係。
- `review_actions`：以最新錯答 AnswerEvent 為依據保存複習／暫緩確認。原有 action receipts 保存操作意圖重播。
- `cycle_closed_at`：本輪明確結束時間。已完成且沒有錯答待補強的既有初篩，只以原完成時間補入此新欄位，不修改原有欄位。

沒有新增另一份答案或分數資料。初篩版本涵蓋補強建立、生成進度、作答與複習決策，晚到讀取不覆蓋較新狀態。所有更動都在同一 StudySession 的短交易中檢查 owner、scope、版本及操作意圖。模型仍在交易外；刪除教材一併清理初篩與補強，晚到工作不能恢復它們。

公開題組／列表為 `assessment-set/v2`／`assessment-set-list/v3`，進度為 `learner-progress/v3`，恢復為 `study-resume/v3`。受控前後端一起升級，不保留舊公開協定 reader；已存題目與答案按原資料契約讀取。

| 操作 | 路徑／內容 |
|---|---|
| 複習／暫緩 | `POST /v1/study-sessions/{sid}/assessment-sets/{root}/reviews`；Claim、review/defer、預期初篩版本、Idempotency-Key |
| 建立補強 | `POST .../{root}/remediation`；預期初篩版本、Idempotency-Key，伺服器選擇已複習的錯誤重點 |
| 結束仍有暫緩的本輪 | `POST .../{root}/close-cycle`；預期初篩版本、Idempotency-Key |
| 初篩／補強整組交卷 | `POST .../{set}/submissions`；原子保存所有答案並結束本組，沒有待補強時同時結束本輪 |
| 讀取／接續 | 原 GET；回傳同一 `cycle` 投影，不生成題目或寫入複習狀態 |

Worker 剛好發布題目時，一致性讀取可能回 snapshot 衝突。前端只對這種 GET 衝突最多讀三次，間隔 100／200 ms，不重播建立、作答或模型請求。切換題組路由後由新頁讀取狀態，避免同時再讀上一條路由。

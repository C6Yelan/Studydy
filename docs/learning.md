# 學習與評量

[文件入口](../README.md) · [使用指南](usage.md) · [教材處理](materials.md)

## 學習與題組身分

同一使用者、教材與知識結構版本對應持久 StudySession。不同觀念可各自保留題組，同一 session／觀念只保留一組進行中的題組；讀取不建立 session 或重算答案。

題組的 owner、知識結構版本、觀念及成員決定作答授權，導覽焦點不改變授權範圍。

## 起始程度與快速檢測

建立教材時，在「確認教材」或主題的「確認學習範圍」設定程度與選填目標。預選第一項；舊教材未設定程度時，第一次開始學習仍會開啟置中對話框。程度按教材保存，新增內容沿用；之後可在教材頁修改，只影響後續安排，已完成重點、進行中題組與 XP 保留。

| 程度 | 後續安排 |
| --- | --- |
| 第一次接觸，或還不太熟 | 從基礎概念開始，依先備順序直接作答。 |
| 學過了，想跳過已經會的 | 先做約 15 題快速檢測，答錯的概念優先學、答對的往後排。 |
| 想找出還不會的地方（例如準備考試） | 從答錯過的弱點開始；沒有作答紀錄時先做快速檢測。 |

第一項保存為 `some_knowledge`；舊 `beginner` 與 `some_knowledge` 都顯示第一項，讀取不改寫既有值。所有程度直接進入題組，不再先顯示整頁教材重點。非作答狀態可展開教材說明，記住同一瀏覽器上次的展開選擇，不綁程度；作答中隱藏教材說明。

目標可選日期與 60／80／100%，略過不建立目標；地圖建好後自動安排每日關卡。上傳確認先保存設定才開始分析，保存失敗留在確認頁；從主題建立於確認範圍時一起保存。補充既有教材不覆寫原程度或目標。

程度只由學生自選，不從分數推測或分級。快速檢測的種類為 `material_diagnostic`，與既有單概念第一組的 `diagnostic` 分開；每題仍綁定自己的概念、重點、來源及私密答案。題組與模型工作沿用既有持久機制。

診斷答對只依現行規則完成該題檢測的重點。後續路線先處理答錯與未測的概念，再回到只測了一部分的概念補剩餘重點；不把一題答對擴大成整個概念完成。所有可檢測重點確實完成時，才沿既有完成流程結束學習。一般未完成概念的後續題組跳過已完成重點；學生主動選擇已完成概念再次練習時，仍可練習整個概念。

同一版本已有快速檢測時，進行中接續、完成後沿用結果；切換程度不自動重做。開始學習請求保留同一意圖的結果，網路重送不會因原題組剛完成而另建一組。beginner 不再免建題組；只有目標概念無可檢測重點時仍不建。舊冪等收據（包括原本未建題組的結果）原樣重播，新開始意圖才套用目前建題組規則；route_order及既有題組紀錄不改。

## 目標日期與分天關卡

每份教材可設定目標日期與掌握目標：60% 及格、80% 熟練、100% 精通。比例以可檢測重點中真正完成的數量計算；同一概念內相同來源與文字合併成一個檢測目標，不把概念數當成重點數。零個可檢測重點不會顯示為達標。達成設定比例只表示「目標達成」，不改寫整份教材或 StudySession 的完成狀態。

計量保留現有作答與版本承接規則。概念可能因承接而標為已完成，但其中仍有缺少完成證據的重點；這些差額不補造成已完成，另列手動複習入口，不擅自把已完成概念加入自動路線。

目標自動跟隨教材新版，保留日期與比例、重算點數及每日安排。目標區顯示如「教材已更新，重點數 52→60」的提示；關閉提示只記錄已看過的版本，不重新設定目標或重排今日量。

日期依 Asia/Taipei 計算，剩餘天數包含今天及目標日。每天日初依剩餘需完成點數除以剩餘天數、向上取整得到今日量；設定／修改目標或教材更新時，以重排當天日初的真實完成量重算配額與原排期基準。當天所有真實完成重點都計入今日完成，包括重排前及當天才恢復可測的重點，不清零或從重排點另計；配額也不因每次作答重新增加。為固定當日配額採用的可測範圍，只保存當日計量基準，不拿它排除新的真實成果；未來關卡仍由目前資料推算，不存固定日程。

「落後 N 個重點」比較原排期截至昨天應完成量與目前實際完成量，不把今天尚有時間完成的部分算成落後。今日關卡依目前起始程度路線排列，未完成弱點優先；保留完整概念與原子交卷，因此尚未完成時，介面分開顯示今日目標量與實際安排量；今日關卡完成後改顯示完成狀態與實際完成的重點數。超過每日 20 個可檢測重點時提示調整日期或目標，不截斷計畫、不自動修改設定。

教材的「學習與測驗」分頁顯示目標、今日關卡與未來預覽；首頁今日任務列出各份有目標教材的今日關卡，群島摘要顯示倒數或目標進度。預覽會隨真實進度與教材版本調整，不表示未來重點已完成。

## 準備與發布

題數由觀念中可出題的重點決定。題組保存計畫、執行快照、逐題狀態與 lease；worker 在交易外生成候選，驗證後保存並發布。

生成器提出候選；獨立檢核只取得來源、題幹與重排選項，不接收答案鍵。發布要求唯一答案與候選正解一致、來源有效且不重複已發布題目。通過正確性檢查後才依品質提示排序，干擾選項較弱不等於無安全題。

公開 API 不暴露準備中的題目或私密答案。失敗可重試未完成題；已有可用題時可選部分發布，其餘重點維持未檢測。每組使用建立時封存的模型設定，調整設定不改寫已保存題組。

## 交卷

提交包含全部已發布題目的選項、expected_set_version 與 Idempotency-Key。少答、重複成員、無效選項或範圍不符都會拒絕整次提交。

答案、事件序號與題組完成狀態在同一交易保存，失敗全部回滾。後端依私密答案評分；相同意圖重播不重複計分，也不覆寫已保存答案。版本衝突須先同步，回應遺失可查回結果。

## 學習重點與概念完成

第一次檢測答對，該重點立即完成。答錯後需連續答對兩道不同題（依 semantic identity 判別）；再次答錯會重新累積。重點一旦完成，之後再次練習的錯誤不撤銷完成。原始 diagnostic／remediation、正誤與答案事件仍完整保留，不另形成掌握度 gate。

概念主要狀態只有「尚未開始／進行中／需要加強／已完成」。全部可檢測重點完成時，概念已完成；有錯題尚待完成則需要加強。題組的準備、失敗及本次練習結果不覆蓋概念狀態。測驗頁僅列出已有正式作答紀錄的概念，依既有完成狀態分為尚未完成與已完成；已完成概念提供「再次練習」；地圖側欄讀完完整重點後，可直接開啟或接續題組。

NO_SAFE_ASSESSMENT 或部分發布時省略的重點是系統能力限制，不算使用者答錯，也不形成永久補強 gate。有部分可檢測重點時，以這些重點判定該次完成；零可檢測時不自動完成，顯示「此概念目前無法提供可靠檢測」，允許繼續下一概念。已有題目而未作答的重點仍未完成。

完成狀態由 [learning_states.py](../backend/src/learning_adaptation/learning_states.py) 及歷史題組重建，不批次改寫過往答案。已完成 session 仍可開啟再次練習；單純閱讀或改變導覽焦點不重開 session。

## 學習診斷與概念難度

教材的「學習與測驗」分頁提供整份教材的學習診斷，API 使用 learning-diagnosis/v2。診斷在讀取時由既有教材與真實作答計算，不新增學習事件，也不改變重點完成規則；題組診斷與 set_id 查詢已移除。

優勢只列所有可出題重點都完成的概念；弱點列尚待補強的重點。每點保留完整重點文字（不截首行或80字）、累計作答／答對數、補強連對數與所需連對數、完成旗標及原文來源。初答正確即完成，答錯後須連續答對兩道不同題，沿用既有完成規則。

「建議先複習」最多列 3 個概念，候選為有未完成弱點或符合「你的難點」的概念。依弱點重點數由多到少排列，同數時優先列個人難點；已無弱點但長期易錯者以弱點數 0 排在後面。每項只顯示概念名稱、一句原因與複習按鈕，不重複弱點全文。

難度由教材結構在讀取時計算，回傳該版本所有概念。先備鏈深度至少 3 層，或包含至少 5 個重點，標為「預估偏難」；根節點深度為 0，只計 prerequisite 關係，原因列出實際先備深度與重點數。不替其他概念顯示「一般」標籤。

「你的難點」依概念累計至少作答 3 題且錯誤率達 50% 判定，附真實錯誤率與答錯／作答數；不足 3 題不標記。補強完成不直接移除這個標記，後續作答使累計錯誤率低於門檻才移除；「弱點」則只表示尚未補完的錯誤重點。

地圖節點、概念詳情與概念卡顯示標記，詳情可查看結構原因，教材診斷的難點清單可直接前往複習。舊卡組與舊學習紀錄維持原版本，不套用新版概念。

## 學習活動與地圖區域

`GET /v1/learning-activity`（`learning-activity/v3`）由現存作答、概念卡標記、Podcast 收聽與刪除前保留的每日計量彙總，已取得徽章另存永久表；只能讀自己的紀錄，以台灣日期為界。回傳連續天數、累計作答／答對數、經驗值（XP）與等級、今日任務，以及徽章（`badges`）。讀取失敗時頁首與首頁隱藏相關數字，不顯示推測值。概念完成的作答重播在 API 程序內保留各版本學習計畫的精簡對應（以使用者、教材、版本與計畫雜湊為鍵），作答與可出題範圍每次即時讀取。

`GET /v1/learning-activity/rhythm?period=week|month|quarter|year&offset=N`（`learning-rhythm/v1`）回傳一段區間每天的作答／答對數、標記的卡片張數（`card_reviews`，同一張卡每天算一張）、實際收聽秒數與是否有學習，供個人檔案的學習節奏使用。週為週一到週日、月為自然月、`quarter` 為 13 週、`year` 為 52 週（後兩者都以本週日為最後一天）；`offset` 是往前翻的頁數，各區間都約可翻十年（週 0–520、月 0–120、`quarter` 0–40、`year` 0–10，超出回 400，畫面的「上一個」也在上限停用），每次最多 364 天。與學習活動共用同一份每日彙總：刪除教材前先折算不含內容的每日紀錄，所以刪除後仍可回顧原有作答數、標記張數與收聽秒數。另回傳 `first_day`（最早有紀錄的日期，沒有紀錄為 null，畫面據此決定能否再往前翻）與目前連續天數。

### 經驗值、等級與連續天數（規則 `xp-rules/v4`，可依需要修改）

規則常數集中在 [learning_activity.py](../backend/src/runtime/learning_activity.py)；修改時一併更新版本字串與本節。

| 來源 | XP | 判定 |
| --- | --- | --- |
| 作答 | 答對 +10、答錯 +3 | 同一份教材的同一題（題目與正解相同的 semantic identity）只算第一次作答；重送與再次練習同一題不重算。 |
| 概念首次完成 | +30 | 依作答時間重播「重點完成」規則（初答正確即完成；答錯後須連續答對兩道不同題），概念的可出題重點全部完成的那一筆作答即為首次完成時間；目前確認無法出題的重點不列入。同一份教材的同一概念跨版本只算一次。 |
| 概念卡標記 | 每張 +2，單日上限 40 | 卡片以「卡組＋概念」識別，同一張卡同一台灣日期只算一次；距上一次標記（任何卡）不到 3 秒的不計分，連續狂點不加 XP。 |
| Podcast | 每實際收聽滿 5 分鐘 +5 | 以每個台灣日期的實際收聽秒數合計，單日上限 60。 |
| 目標與關卡 | 分天關卡每關 +15（單日上限 45）；在目標日以前達成目標 +50 | 交卷時記錄（`goal_milestones`）：今日配額大於 0 且今天真實完成的重點達到配額，每份教材每天一關；目標已先達成、配額為 0 的日子不算。準時達成：該次交卷後達到掌握目標、當天不晚於目標日，且設定（或最近一次修改）目標那一刻尚未達標；每份教材只算一次。 |
| 克服難點 | 每個 +20 | 依作答時間重播同一教材同一概念的作答，與作答 XP 相同只採計每題（semantic identity）第一次作答，再次練習的重複題不計：累計作答 ≥3 題且錯誤率 ≥50% 即為「你的難點」（與學習診斷相同門檻），之後累計錯誤率降到 50% 以下的那一筆作答為克服；每個概念只算一次，之後再變成難點不重算。 |
| 起始程度診斷 | 每份教材 +20 | 快速檢測題組（`material_diagnostic`）第一次完成；作答本身仍照「作答」計分。 |

- 等級（分段曲線 `LEVEL_SEGMENTS`，參考原神冒險等級）：前幾級升得快，每進入新的一段需求明顯跳一階，高等級很難升。第 n 級升到 n+1 所需 XP 為所在段的基數＋段內增量×(n−段起點)：

  | 等級 | 每級所需 XP | 累計到該段起點 |
  | --- | --- | --- |
  | 1–4 | 100、150、200、250 | 0 |
  | 5–9 | 500 起，每級 +100 | 700 |
  | 10–14 | 1400 起，每級 +150 | 4200 |
  | 15–19 | 2600 起，每級 +200 | 12700 |
  | 20–29 | 4500 起，每級 +300 | 27700 |
  | 30 以上 | 9000 起，每級 +500 | 86200 |

  回傳目前等級、本級已得 XP、升級所需 XP 與總 XP（`sources` 分 answers、concepts、cards、podcast、goals、difficulties、diagnostics）。等級由累計 XP 即時推算：已取得的等級徽章永久保留，不隨曲線重算收回；xp-rules/v4 上線時，克服難點與起始程度診斷依既有作答回溯計入，分天關卡與準時達成目標沒有過去紀錄可推導，從部署後開始累計。沒有排行榜。
- 連續天數：當天有作答、標記概念卡，或實際收聽滿 1 分鐘（60 秒），即算有學習；今天尚未有活動時保留到今天結束。
- 只依已保存的逐筆作答、概念卡標記（間隔複習時期的評分沿用為標記）、Podcast 收聽紀錄、診斷題組與交卷時記錄的關卡／達標計算。沒有紀錄的過去活動不補算、不推測；瀏覽器舊有的播放位置只上傳位置，收聽秒數為 0。
- 刪除教材、卡組或 Podcast 前，先保存日期與來源的 XP 基數、次數、秒數；卡片另留不含內容的原始身分、事件編號與時間，維持同卡每日去重與跨卡 3 秒間隔。合併現存與保留紀錄後才套每日上限，XP、等級、連續天數與個人累計不因刪除倒退。題目與答案不保存；同教材同題首次計分在刪除前折算，刪掉後重新上傳的新教材可重新取得首次作答 XP。
- 概念完成時間是重播推導值：與畫面的「已完成」使用同一個重點完成規則，但不重建題組補強流程的每個中間狀態；若日後確認某重點無法出題，完成時間依目前狀態重新推導。

### 今日任務

由真實資料推導、不另存，沒有對應資料的任務不顯示：

1. 概念卡：今天標記 5 張概念卡，與 XP 相同的計分標記才算（同一張卡算一張，距上一次標記不到 3 秒的不算；卡片不足 5 張以現有張數為準）。沒有卡片就不顯示。
2. 繼續學習：今天完成 1 次題組作答即完成；沒有進行中的學習（目前版本的 active／no_safe 學習）且今天也沒完成題組時不顯示。
3. Podcast：今天聽完任一集即完成；建議最近收聽、還有未聽完分集的節目。沒有未聽完的分集且今天也沒聽完時不顯示。

全站頁首經驗條右邊顯示帳號空間（大於 1280px 為儲存圖示、細進度條、已用／上限；1280px 以下為圖示與整數百分比，已用大於零但不足 1% 顯示「<1%」），點按展開分類分色堆疊條與各類大小（教材原檔與轉換檔、Podcast 音訊、Podcast 影片、分析資料、處理中預留），以及佔用最多的前 5 份教材；可點名稱進入教材。預留已包含在已用空間中，明細加總等於已用，滿額警告保留。教材工作區不顯示空間面板。全站頁首在連續天數左邊顯示等級盾牌與本級經驗值進度（大於 1280px 附「本級已得/所需」數字；721–1280px 中央導覽兩側最窄，只留盾牌與連續天數；手機留盾牌與細進度條），點按進入「成就」頁（`/achievements`：等級卡、經驗值計算方式與徽章）；首頁右欄是今日任務與快速存取（接續學習、最近收聽且未聽完的 Podcast），累計總覽數字、可切換區間與翻頁的學習節奏以及登入裝置在「個人檔案」（`/profile`，右欄是名稱與密碼設定）。桌機頁首導覽也有「成就」與「個人檔案」。升級與新徽章由伺服器原子領取，跨瀏覽器只顯示一次；前端接線依 API 契約採 POST /v1/learning-activity/celebrations/claim，先顯示升級並尊重減少動態設定。

### 徽章（規則 `badge-rules/v7`，可依需要修改）

徽章併入 `GET /v1/learning-activity` 的 `badges` 欄位（`rule_version` 與 `items`），與 XP 共用同一次計算（含概念完成的作答重播），不多一個請求。只由下表的真實紀錄即時推導，不存取得狀態、不補算沒有紀錄的過去活動；計入上線前既有紀錄。無法由既有資料推導的分天關卡、準時達成目標與匯出，分別在交卷與匯出成功時寫入最小紀錄（migration 0019 的 `goal_milestones`、`learner_exports`），從部署後開始累計。規則常數 `BADGES` 在 [learning_activity.py](../backend/src/runtime/learning_activity.py)，名稱與層級在 [Badges.tsx](../frontend/src/features/badges/Badges.tsx)；修改門檻或新增徽章時一併更新版本字串、API 模型、兩邊程式與本表。

v7 新增目標與分天關卡、克服難點、起始程度診斷、筆記與個人註記、多元教材、匯出、Podcast 節目、組合成就與彩蛋。v6 參考 Duolingo（連續天數與累計 XP 分層、無失誤課程、夜貓／早起等驚喜成就、個人紀錄）、Khan Academy（由易到難的徽章等級與挑戰）、Quizlet（連續答對）與 Anki（累計學習天數熱力圖）的設計，只挑 Studydy 既有紀錄能判定的項目：新增學習天數、題組完成、Podcast 聽完三個系列與多個高層級，以及隱藏成就與逐步揭曉的成就鏈；排行榜、好友等沒有對應資料的項目不做（v6 當時沒有的每日目標，v7 以教材目標的分天關卡判定）。

- 每個徽章回傳 `earned`、`earned_on`（台灣日期）、`progress` 與 `target`（進度不超過門檻）。累計型徽章的取得日期是累計第一次達到門檻的那一天；連續天數徽章是第一次連續達標的那一天，之後中斷仍保留，未取得時進度為目前連續天數；等級徽章是每日 XP 累計第一次達到門檻的那一天，進度為目前等級。目前所有條件都能推導日期；若日後規則推導不出日期，`earned_on` 為 null，畫面只顯示「已取得」。
- 已取得徽章與取得日期永久保存，內容刪除或日後規則改版也不收回。未取得的更高級徽章進度依現存計量與可保留的學習統計計算，部分內容相關進度可減少。部署後首次計算保存現有已取得徽章，不能回補早已刪除的紀錄。

- v7 上線時的回溯：克服難點、起始程度診斷、筆記、個人註記、各種上傳、Podcast 節目與主持人、全能島主、對症下藥、影音學習者、多媒體大師、深夜電台、宿敵與現學現用都由既有紀錄推導，計入上線前的活動；立下目標以 0019 回填的時間計（既有目標回填為目前的 `baseline_at`，修改過的目標會晚於實際設定日）；分天關卡、一週闖關、準時達陣、壓線達陣與匯出沒有過去紀錄可推導，從部署後開始累計。
- 「成就」頁左欄是等級與經驗值（本級進度與「再 N XP 升到第 X 級」、各來源比例長條、七種來源的規則與已得 XP，桌機捲動時固定），右欄是成就總覽：依稀有度的取得數，下方分成「已取得」與「未取得」兩區，每個成就（含特殊成就）獨立一格，系列名稱與層級是格內小字。未取得的系列層級顯示條件與真實進度；未揭曉的特殊成就只有「？？？」、稀有度與提示，不顯示進度。讀取失敗時不顯示徽章區。前端不認得的代號不顯示。
- POST /v1/learning-activity/celebrations/claim（celebration-claim/v1）同一交易取得未看過的最高等級與徽章並標記已看過，兩台同時請求只有一台取得；回傳後視為看過，網路遺失回應不重播。遷移時既有帳號首次計算的全部已得等級／徽章標看過，不補跳歷史事件。前端接線後以此取代 localStorage 判定，升級優先於徽章。升級與徽章提示都是對話框，不會自動關閉（WCAG 2.2.1）；按「太好了」、Esc 或點背景關閉，焦點回到開啟前的位置。

### Podcast 收聽進度

migration 0010 新增 `podcast_episode_progress`（每集播放位置與首次聽完時間）與 `podcast_listening_days`（每集每天的實際收聽秒數），對 Podcast 外鍵 ON DELETE CASCADE。`GET／POST /v1/podcasts/{id}/progress` 只接受自己且已完成生成的節目；開啟時以伺服器的最近位置接續（跨裝置），伺服器沒有紀錄時才上傳此瀏覽器舊有的位置（`legacy`，不含收聽秒數）。

播放中每 15 秒、暫停、換集、聽完與離開頁面（keepalive）時回報位置與「距上次回報實際播放的牆鐘秒數」。伺服器依序處理同一學生的回報，只採計不超過距離上一筆採計的實際經過時間＋2 秒寬限、單次 60 秒及集長兩倍（0.5 倍速）的部分，重送、多分頁同時播放或離線補報不會灌水；超過上限的部分不採計。播放到距片尾 1 秒內或播放結束，且這一集累積採計的實際收聽秒數達集長 45%（最快 2 倍速從頭聽到尾約為一半）才標記該集聽完；只拖到片尾不算，已標記的聽完紀錄不回溯重算。刪除 Podcast 前先折算每日收聽秒數，再移除播放位置；教材清除後每日學習計量仍保留。

`GET .../knowledge-structures/{revision}/regions` 把概念分成地圖區域，只作呈現用途，不改寫知識結構或 hash。多來源教材依每個概念重點 Evidence 最常引用的來源檔分區（區名為去副檔名的檔名）；只有一個主要來源時依學習順序切成至多四段，`basis` 標為 `learning_order`，畫面註明「非教材章節」。前端只在區域剛好涵蓋地圖全部概念時分區，否則維持不分區的導覽。

### 章節分區（0012）

`knowledge_chapters` 是知識結構版本的衍生資料（主鍵 learner／material／structure_revision，隨版本刪除），不產生新版本，也不改卡片、進度、XP 或徽章。新版本發布時在同一交易排入 `pending`；背景 `studydy-chapters` worker 一次處理一份，有教材分析排隊或進行中時先等待。程式依學習順序送出概念名稱、引用頁碼與主要來源檔（`runtime/knowledge_chapters.py` 的固定提示，hash 存於 `prompt_sha256`），模型只回各章起點與名稱；每次請求的輸入估算＋輸出上限 ≤ 32K tokens，概念超過 600 個時依學習順序切窗並盡量在來源檔改變處切開。程式驗證每個概念剛好一章、章數在合理範圍、每章至少 3 個概念、名稱非空不重複不空泛且 ≤ 24 字；不合格帶原因補正一次，仍不合格只有該窗退回來源檔分區。全部窗合格為 `ready`、部分退回為 `fallback`、全部不合格或工作失敗為 `failed`，不無限重試；服務關閉時進行中的工作放回佇列，租約過期中斷兩次判定失敗。

regions API 有 `ready`／`fallback` 章節時回 `basis: "chapters"`，`partial` 標示部分退回；多來源教材另回 `groups`（來源檔分區），每章以 `group_id` 歸入成員最多的來源檔。前端在章節超過 24 個且有兩個以上島群時兩層呈現（來源檔＝島群、章節＝島，提供「跳到章節」選單），否則一層。沒有可用章節時沿用上述來源檔／學習順序分區。

既有教材的一次性回填（只排入佇列，不在命令內呼叫模型）：

```bash
docker compose --env-file .env -p studydy -f compose.yaml -f compose.tunnel.yaml \
  -f compose.app-update.yaml exec backend /app/backend/.venv/bin/python -m runtime.container_app \
  queue-chapters [--material <material_id> ...] [--requeue]
```

不帶 `--material` 時排入所有已發布、未清除且目前版本還沒有章節列的教材；`--requeue` 連已完成（含 `failed`）的也重新排入。

## 個人名稱與全站搜尋

`GET／POST /v1/profile` 讀寫學生自己的顯示名稱（migration 0008 新增的 nullable `learners.display_name`）。名稱經 NFC 正規化並去除前後空白，空字串視為清除；限 20 字、不得含控制字元或換行，DB 約束同步把關。名稱只顯示在頁首與首頁問候語，不進入 `learner-identity/v1`，未設定時沿用原問候。

`GET /v1/search?q=` 只查自己未刪除教材的名稱，以及各教材目前版本（head revision）的概念名稱與別名；資料來自每份教材一筆的 outline 讀取索引，不掃描重點全文。排序依完全相符、開頭相符、名稱包含、別名相符；概念最多 30 筆並以 `concepts_truncated` 標示。選取概念後開啟該教材地圖並直接顯示概念詳情；重點全文搜尋仍在各教材地圖內進行。

清單頁（我的教材、概念卡、Podcast）不另設搜尋框，統一使用頁首搜尋；地圖、教材來源、卡組內概念清單等功能內的搜尋仍各自保留。進入單一教材後由教材頁首（返回、教材名稱、分頁、教材問答與頭像選單：個人檔案／成就／登出）取代全站頁首與手機底部導覽，不顯示全站導覽、搜尋與連續天數；地圖搜尋與概念統計浮在地圖上。教材來源數、頁數與建立日期放在教材名稱的提示與「教材來源」分頁。從全站「概念卡」「Podcast」開啟、沒有教材網址的頁面仍用全站頁首。頁首搜尋：開啟時另讀一次卡組與 Podcast 清單，在前端依名稱與所屬教材比對，與上述教材、概念結果一起列出；這兩份清單讀取失敗時只少這兩類結果並提示。

## 恢復與版本承接

Progress 與 resume 使用同一 DB snapshot，核對 session、run、知識結構版本、題組成員與事件序號。URL 可定位原題組；讀取、刷新與重新登入不產生題目或答案事件。

下一步由後端進度決定，前端提交 guidance_revision 套用操作。更新教材後，來源、文字及區塊一致且可唯一匹配的重點能承接證據；變更或匹配有歧義時不承接。

承接不複製答案事件，也不修改原題目、正誤、時間或版本。原題組仍依其固定版本讀取。

### 移到新版（卡組與學習進度）

教材更新（新增來源後更新地圖或加入補充學習）產生新版本後，舊版的卡組、學習標記與學習照常保留，不會自動搬動。教材頁（地圖、卡組、Podcast、補充學習、來源各分頁上方）在學生仍有舊版卡組或學習時顯示「有新版本」，按「移到新版」先看預覽，確認後才承接。Podcast 維持建立時的版本，不承接。前端只在教材保留舊版本（`available_structures` 有 head 以外的版本）時才讀取預覽。

`GET /v1/materials/{id}/version-move` 回傳預覽（`version-move-preview/v1`）：可移動的舊版卡組（未刪除、已生成、尚未移過）與最近一個舊版學習，各自列出可對應的概念、無法對應的概念及原因、會沿用的學習標記數、可直接沿用的卡面數，以及維持舊版的 Podcast 數；`preview_digest` 綁定這份預覽。沒有可承接項目時 `card_sets` 為空、`study` 為 null。`POST` 同一路徑需要 Idempotency-Key 與預覽的 `preview_digest`、`to_revision`（目前 head）及要移動的卡組／是否移動學習：重送同一個鍵取得同一筆結果；預覽在確認前變了（教材又更新、另一個分頁已移動）回 `VERSION_MOVE_STALE`，前端重新讀取預覽。知識結構版本不可變，預覽在第一次完整驗證後於 API 程序內沿用由結構推導的概念名稱、順序與對應（千頁教材首讀約 6 秒，之後約 0.5 秒）；卡組、排程與學習進度每次即時讀取，確認承接時仍重新讀取並驗證完整結構。

概念對應規則（`map_concepts`，[source_identity.py](../backend/src/knowledge_map/source_identity.py)）：

1. 依原文區塊：舊概念各重點引用的教材原文區塊，以與既有承接相同的來源身分（原檔／normalized hash、來源頁碼、區塊順序、範圍與原文）比對。引用最多這些區塊的新概念若唯一，且涵蓋舊概念至少一半的區塊，就是對應概念。新版可能改寫名稱與重點文字，但原文區塊不變，所以以此為主要依據。
2. 依名稱：沒有符合第 1 項時，舊概念名稱或別名（NFKC、不分大小寫、合併空白）與唯一一個新概念的名稱或別名相同。
3. 其他不承接並列給學生看：區塊分散到多個新概念（split）、名稱對到多個新概念（ambiguous）、找不到（not_found）。不猜測語意相近的名稱，也不拆分舊概念；多個舊概念可以對應同一個新概念（新版合併）。

卡組：在新版建立同名卡組，概念依舊卡組順序換成對應的新概念（合併的只留一張），無法對應的不放入。每張新卡沿用對應舊卡的學習標記（`card_review_states`；合併時取最近一次標記的那張）。來源輸入（重點文字、原文節錄與相鄰關係）完全相同的卡面直接沿用並換成新版的 Claim／Relation／Evidence ID，不呼叫模型；其餘卡面由既有卡片生成流程依新版內容製作，完成前新卡組不列入需要加強。舊卡組保留原卡面、標記與事件，標示「已移到新版」並不再列入需要加強與標記統計；新版卡組被刪除後，舊卡組可以再移一次。

學習進度：在新版建立（或沿用已有的）學習，從對應到的目前概念接著學。新概念對應到的所有舊概念在舊版都已完成時，新版標示為已完成（`study_session_moves.completed_concept_ids`，由進度推導的「曾完成概念」讀取）；只完成一部分的合併概念、或對應不到的已完成概念列為不承接，需在新版完成。內容沒有改寫的重點仍依上段規則沿用作答證據。舊版學習、題組與作答都不改寫，仍可依固定版本讀取。

XP、徽章與連續天數只由作答、標記與收聽事件推導，承接不新增事件，因此不會增加或重算。移到新版的卡片沿用最初那張卡的身分（`card_set_moves.concept_map`），同一天在舊卡與新卡各標一次仍只算一張（卡片 XP 與今日任務都是）；概念完成 XP 仍依作答重播，承接的完成不另給 XP。

## 概念卡學習標記

學生自己把每張卡標成不熟或熟悉（API 值 `forgot`／`remembered`），不排程、不設到期日，也沒有「新卡」；沒標記的卡就是未標記。標成不熟的卡列入「需要加強」。每張卡以「卡組＋概念」識別，標記可隨時改。

`card_review_events` 逐筆保存標記（供 XP、今日任務與徽章計算），`card_review_states` 保存每張卡目前的標記與次數（migration 0009）。`POST /v1/card-sets/{id}/reviews`（`card-review-submit/v1` → `card-review/v2`）需要 Idempotency-Key 與送出前看到的標記次數：重送同一個鍵取得同一筆結果；另一個分頁已標記過時回 `CARD_REVIEW_CONFLICT`，不重複計次。`GET /v1/card-reviews`（`card-reviews/v2`）回傳各卡組的張數與不熟／熟悉張數，以及需要加強的卡片（較久沒標記的在前，每次最多 20 張）；帶 `card_set_id` 時另列出該卡組每張已標記卡片的標記；帶 `material_id` 時只計這份教材的卡組（20 張上限也在這份教材內計算）。只列生成完成、未刪除、教材未刪除且尚未移到新版的卡組。

概念移出卡組後標記保留但不列出，加回時沿用；卡組軟刪除後不再列出；教材清除實際刪除卡組時，標記與事件一併刪除。「需要加強」是獨立頁：概念卡頁的入口列開啟 `/concept-cards/review`（所有卡組），卡組頁標題旁的入口開啟 `/materials/{id}/concept-cards/{card_set_id}/review`（只看這個卡組）。教材內概念卡分頁也有入口列，顯示這份教材標成不熟的張數，開啟 `/materials/{id}/concept-cards/review`（只看這份教材的卡組，返回與分頁都回到這份教材）；瀏覽卡片時每張卡下方也能直接標記。加強頁顯示與卡組瀏覽相同的概念卡（圖卡、完整重點與來源頁碼，卡片內容經卡組瀏覽 API 讀取），一次一張並顯示「第 n / N 張」，卡下方標記不熟／熟悉；標熟悉即離開需要加強。一輪看完就停，按「再加強一輪」才重新讀取；另一個分頁已標過的卡直接跳過、不重複計次。

## 概念圖卡

新卡組保存選材與知識結構版本，依序準備來源、整理與設計卡面、核對來源，再開啟卡組。模型以整個概念為單位合併與取捨重點，選擇 focus／compare／flow／grid 版型、區塊順序、內建圖示及有來源支持的箭頭；優先一張，必要時最多三張處理不同核心問題。卡面依實際字型與可用寬度換行，標題、結論、區塊與畫布高度隨內容調整；不以後端估算字寬退件，也不截掉內容。次要細節可留在完整原文；顯示的結論仍須保留必要條件、否定、數值與主體責任。每個區塊與箭頭由模型的局部來源編號連回原 Claim／Relation／Evidence，避免整段改寫無法套入表格欄位。

來源核對只針對實質的事實、引用與關係錯誤；不因措辭偏好、例子多寡或未重述每段原文退件。格式或核對失敗時，保存實際候選卡面，只帶入目前未解決的回饋，再做一次定向修正；仍未通過就保留失敗狀態，可重試，不把長原文回填當成完成。工作分步保存，已完成觀念可續接，同擁有者、教材版本、設計政策與模型通道內可重用。既有卡組保留原卡面，不提供整組重新生成操作。

概念卡使用共用 `request_semantics`：`STUDYDY_TEXT_TEST_PROVIDER=codex-exec-luna` 是目前明確啟用的暫時 Luna 通道；未啟用時使用 runtime lock 的 Gemma，透過既有 `STUDYDY_SEMANTIC_BASE_URL`／Pod 連線層，不新增 SSH／Pod 連線程式。新工作保存模型、revision 與協定身分，通道中途改變時拒絕混用結果；另建卡組才綁定新設定。Gemma 回傳的 token 用量如實保存，Luna 未提供精確用量時只記錄估算與實際呼叫／耗時。

`needs_review` 在完整重點保留待確認提示。圖卡不會因繪製完成而取得品質驗收。保存版本讀取失敗時可重新讀取，不改用目前的教材版本；來源入口沿用該版本的 resolver。預覽不經 PNG 編碼／解碼，也不提供放大功能；下載直接編碼目前 Canvas 的相同像素。卡組首次只讀取 8 個觀念及必要的相鄰概念、關係與來源，背景預取下一批；跳選直接取得目標批次，不下載整份知識結構。文字最多保留目前及鄰近使用的三批；背景只預繪下一張，帳號工作階段在記憶體最多保留最近 8 張 Canvas（約 28 MiB 像素），依教材版本、概念、精簡文字及頁碼重用；失敗不留快取。快取隨帳號 API 物件釋放，重新整理或帳號切換後重新產圖，不寫入伺服器圖片或瀏覽器持久儲存；經核對的卡面設計 JSON 隨卡組保存，只在同一擁有者、教材版本、設計政策與模型通道內重用。舊卡組保留原文顯示，不因升級自動觸發模型。不執行教材提供的 HTML、JavaScript 或 SVG。

卡面使用固定比例，集中顯示標題、核心說明、至多四個重點節錄與小圖。左側選概念，右側單卡預覽；完整條件與全部來源可另開詳細面，不以節錄取代教材。

`card_count` 統一表示包含續圖的實際張數；概念數由選材與生成進度取得。列表或複習頁按卡組版本保存每個觀念的續頁張數，全部備齊後彙總 `card_count`；後續列表只讀摘要，不再下載卡片全文、整份知識結構或繪圖模組。跳選尚未備齊前段頁碼的卡片時顯示觀念內頁碼，不猜測全組頁碼。尚未完成精簡時只顯示生成進度；既有卡組首次補算一次。改名保留張數，選材變更清除重算；保存失敗提供重試，不將未保存結果當成成功。分頁政策更新時須同步前後端的 `layout_policy`，並以 migration 將既有 `card_count` 清為 NULL，再使用同一套排版補算。

建立卡組時，由已驗證的保留版 KS 建立按概念查詢的文字投影；同版本的多個卡組共用。概念投影索引定義於 `0006_read_indexes.sql`，卡組的 `card_count`／`page_counts` 定義於 `0005_cards_and_media.sql`；缺少的投影可補建，不觸發模型。每次分批讀取核對 owner、卡組版本、來源綁定及本批投影 hash，來源連結沿用原 resolver；原文、頁碼、區塊與完整關係來源不截斷。索引隨 KS 的保留／清理生命週期，不另建圖片倉庫。

## 教材文字與語音問答

文字與語音辨識後的問題共用 RAG 路徑。沒有對話指涉時先用原問題檢索；需要還原指涉或取材不足時，Luna 再規劃精確術語，各子問題分別取材。查詢規劃不提供答案依據。檢索補鄰接內容與同概念資料，完全相同的原文去重但保留各來源。對話按 token 預算保留近期完整輪次，超額時才將較早內容與既有摘要合併壓縮；摘要與近期對話共用原歷史預算，沒有固定三輪限制。摘要保留目標、條件、修正與未解問題，只供還原指涉，教材事實仍須檢索原文支持。原始對話不刪除，摘要為有損壓縮，不保證所有舊細節均能保留。

最近使用者的明確更正優先於舊摘要與助理文字，回顧變更時仍保留先後條件。公式須連同相鄰定義與適用條件核對，本輪沒有取到不能說成教材不存在。

Luna 逐段回答並引用本輪原文，獨立核對各段。核對可刪去未支持的附加主張或修正適用範圍，保留有依據的核心步驟；不能藉修正新增事實。資料不足時最多補查一次，同時保留回答與核對階段提出的精確術語，各子問題保有取材名額。保留已通過核對的回答，具體指出未補足部分，不因一個次要缺口丟棄全部答案。新回答保存 `material-answer/v3` 與 passage 引用，不重建舊 claim 索引或轉接舊回答。

問答原文預算為 7,500 個估算 token；歷史合計 1,200，其中摘要最多 550；整次提示與輸出 schema 上限 12,000，另保留模型回答空間。摘要按批次保存處理位置，後續只壓縮新超額的輪次，不重送全部舊對話。使用 o200k 作估算，不把它當 Luna 實際 tokenizer 用量。取材、模型呼叫（含摘要）、各次輸入估算及壓縮前後歷史大小保存在回答的診斷欄位，不顯示給一般學習操作。

錄音先辨識文字，再走同一問答路徑；純文字不呼叫 TTS。答案朗讀失敗時保留文字與引用，重試只重做語音。取消與離開頁面沿用既有媒體清理與工作租約，不跨帳號保留音訊。

辨識提示保留教材題名並加入近期有依據的詞彙，原辨識與理解後問題分開保留；提示不代表使用者確實說過，數字、否定與新條件不得擅改。語音回答採適合直接朗讀的中文表達，使用者要求的原句、精確字面值、公式、條件與數值仍須保留，文字模式不套用口語限制。

已授權的回答音訊支援單段 HTTP Range，拖曳播放不需重新生成音訊；帳號與私人快取邊界不變。

Podcast 依選定概念及關係規劃分集，透過同一索引取得各集引用與同頁鄰接脈絡。原文區塊只放一次，來源編號連回所選概念；與原文完全相同的重點不再重複放入提示，獨立摘要則保留。必要原文全部保留後，再以剩餘容量補鄰接內容；非連續片段明示缺口。不掃描整份教材作每集 context，不因容量不足截斷必要引用或更動既有腳本。

分集保留完整重點，以每集至多 32 個來源重點、8,000 個原文估算 token、10,000 個來源與脈絡合計估算 token 規劃，不再以 2,400 字元拒絕長重點。單一重點的必要原文仍無法容納時，回報 `PODCAST_SOURCE_TOO_LARGE`。教材索引建立成功不代表任意概念選取都能生成 Podcast；模型品質仍須檢查實際講稿與引用。


## 匯出學習資料

各功能頁提供匯出按鈕；只有一種可用格式時直接下載，兩種以上則開啟對話框，以格式卡片選擇後匯出。Podcast 依當下音訊、影片與時間軸的可用格式決定入口。只能匯出目前帳號的資料；沿用該頁保存的教材版本，不改成最新版。匯出不呼叫模型、不新增學習事件，也不改寫原資料。

- 概念卡：整組 Anki（.apkg）、可列印 PDF（A4 每頁兩張）及全部卡面 PNG 的 ZIP。卡面沿用現有 Canvas 與續頁；Anki 正面為概念名稱，背面保留完整重點文字、卡面圖片及來源。跨批讀取核對卡組版本，過程中編輯卡組時拒絕混用版本。卡面每兩張分批送出，再下載單一整組檔案，大卡組不受單次請求的上傳總量限制。每份 PNG 合計最多 512 MiB，每概念最多 16 張、整份最多 2000 張；每人同時最多兩份卡組匯出。超限會說明原因，不截掉部分卡面。
- Podcast：按集匯出由保存音訊（FLAC，舊集為 WAV）在記憶體轉出的 MP3、已完成影片的 MP4，以及具時間軸的逐字稿 Markdown。逐字稿保留保存的主持人名字、段落起訖時間與本集重點／來源；舊集未保存名字時沿用「主持人／來賓」。沒有影片或有效時間軸時不顯示相應格式，不臨時生成或推算時間。
- 知識地圖：完整島嶼圖 PNG 與概念大綱 Markdown。最多 24 個概念時產生一張圖，較大教材沿已保存的區域分圖；單區超過 24 個概念再連續分圖並打包 ZIP。每個概念恰好一次，保留全部概念關係及跨圖連線清單，不以目前視窗或兩層鄰居限制匯出範圍。
- 學習診斷：一頁 PDF 摘要，列優勢／待加強重點統計、建議先複習項目，以及可容納的重點／作答數／來源。弱點先列，省略的重點數明示於頁尾。診斷查詢與 PDF 匯出皆以整份教材為範圍，不再接受題組範圍的 set_id。

影音來源（MP3／M4A／WAV／MP4／YouTube）的引用標為「第 N 段」，文件引用標為「第 N 頁」，與來源按鈕一致。空診斷不印空的建議標題，也不列零筆省略的頁尾。

多格式匯出的進度與錯誤顯示在對話框內，成功後自動關閉並回到原入口；匯出期間保持頁面開啟。失敗保留選取供重試，下載不會以失敗回應冒充檔案。筆記格式詳見[文字筆記](materials.md#文字筆記)。

## 建立前選擇與可達目標

上傳確認時可在尚無 head 的教材保存程度與目標；goal 回應 learning-goal/v2 的 pending_goal 保存日期／比例，發布後在同一交易建立排程。從主題建立的 starting_level／learning_goal 跟 topic 保存，選源建立教材時帶入，不改原 .youtube 保存契約或生成提示。some_knowledge 是「有一點了解」的保存值；改程度只重排後續概念順序，當日已定數量與完成事實保留。

超過每日20點時，goal.suggestions 只提供經現行完整概念排程驗證可達的延後日期／降低比例。每個建議提供實際 target_date／target_percent／daily_points，前端使用既有PUT套用；單一概念本身超過20點而無可行方案時不提供假建議，不改出題或拆點規則。

新問答保存 material-answer/v3 的 paragraphs（text、citation_ids），來源關係只取已核對接受的段落；既有 v2 回答維持原文與來源清單，不猜段落對應、不重新呼叫模型。

### 作答期間的教材問答

普通題組與快速診斷在實際作答時每 20 秒送出 assessment-presence/v1；離頁停止回報，伺服器在 60 秒到期後解除。交卷成功補送 active=false，後端交卷交易也會解除。瀏覽器 ID 以 localStorage 保存並跨分頁共用，只在 presence、文字提問、錄音與重試附上 X-Studydy-Browser-Id；另一個瀏覽器使用不同 ID。作答時移除問答入口，既有回答不新增取消；被拒絕時顯示 ASSESSMENT_IN_PROGRESS 對應提示，保留問題草稿。此機制是避免順手查答案的介面限制，不是裝置驗證。

### Podcast 製作步驟與略過提示

生成頁直接讀取各集 generation.steps 的 script／audio／alignment／video 狀態及 elapsed_seconds；未知排隊數不估填，未選影片不自行補步驟。單集未完成使用不確定進度，多集以已完成集數計數，步驟不折算百分比。omitted_content 只用於逐字稿與本集重點的固定略過提示，不呈現未核對台詞；過半失敗門檻由後端判定，前端沿用 PODCAST_SCRIPT_NEEDS_REVIEW 並說明原因。

### 語音逐句播放與實際耗時

新語音回答整份來源核對完成後，才依句末標點／換行切句（小數點不切），依 index 連續保存。audio_sentences 的 ready 句可由專屬 audio/{index} 讀取，尚未完成回409 VOICE_AUDIO_NOT_READY；每句保留原文，送TTS沿PC6可念化處理。第一句完成即可播放，整份 /audio 只在全部完成後提供串接WAV，舊整份音訊維持可讀。

取消會停止正在製作與待生成句，保留已完成句；失敗後不跳過該句，重試保留已核對回答及已完成音訊。stage 與原status共同描述生命週期，不能以已有某句音訊認定全部完成。timings 記錄 retrieval_ms／answer_ms／verification_ms／tts_queue_ms／tts_synthesis_ms；TTS排隊包含成為下一句後等待worker與provider鎖的實測時間，合成時間由provider回報。重試累加實際已量測耗時，舊資料沒有量測即null，不估填。部署前已核對但配音失敗的回答，重試時才從保存的原回答建立句列，不重新問答或改寫內容。

### 逐句回答語音

依 voice turn 的 stage 顯示查找教材、整理回答、核對來源、等待語音及製作語音；舊資料依原生命週期顯示，不估填耗時。已核對音訊依 audio_sentences.index 順序播放，只請求 ready 的片段；下一句未完成就等待，失敗不跳過。retry 沿用 ready 前綴，cancel 停止待製作句子並保留原取消語意。逐句製作中沿用暫停收音，不新增自動取消；完整完成後才恢復開口打斷。完整回覆保留既有播放器與播放軸，串播進行中不切換成整段重播。

L1確認範圍時，POST /v1/topics/{id}/approve 可同時保存starting_level及learning_goal：未傳欄位保留建立時設定，明確null清除。設定、proposal與搜尋意圖同交易保存；相同key／expected_version重送需相同確認內容，否則TOPIC_CONFLICT。確認改設定後，舊POST /v1/topics建立請求若重送原設定，依既有規則回IDEMPOTENCY_CONFLICT；不新增建立指紋，建立時的網路重試與之後確認分開處理。補充既有教材仍拒絕非空新設定，不覆蓋教材原值。

DELETE /v1/materials/{id}/goal只清尚無已發布head的pending_goal，回learning-goal/v2且goal/pending_goal均null，可重送。已有head一律回409 LEARNING_GOAL_PUBLISHED，保留已發布目標；不提供刪除已發布目標的旁路。

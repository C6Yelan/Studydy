# 學習與評量

[文件入口](../README.md) · [使用指南](usage.md) · [教材處理](materials.md)

## 學習與題組身分

同一使用者、教材與知識結構版本對應持久 StudySession。不同觀念可各自保留題組，同一 session／觀念只保留一組進行中的題組；讀取不建立 session 或重算答案。

題組的 owner、知識結構版本、觀念及成員決定作答授權，導覽焦點不改變授權範圍。

## 準備與發布

題數由觀念中可出題的重點決定。題組保存計畫、執行快照、逐題狀態與 lease；worker 在交易外生成候選，驗證後保存並發布。

生成器提出候選；獨立檢核只取得來源、題幹與重排選項，不接收答案鍵。發布要求唯一答案與候選正解一致、來源有效且不重複已發布題目。通過正確性檢查後才依品質提示排序，干擾選項較弱不等於無安全題。

公開 API 不暴露準備中的題目或私密答案。失敗可重試未完成題；已有可用題時可選部分發布，其餘重點維持未檢測。每組使用建立時封存的模型設定，調整設定不改寫已保存題組。

## 交卷

提交包含全部已發布題目的選項、expected_set_version 與 Idempotency-Key。少答、重複成員、無效選項或範圍不符都會拒絕整次提交。

答案、事件序號與題組完成狀態在同一交易保存，失敗全部回滾。後端依私密答案評分；相同意圖重播不重複計分，也不覆寫已保存答案。版本衝突須先同步，回應遺失可查回結果。

## 學習重點與概念完成

第一次檢測答對，該重點立即完成。答錯後需連續答對兩道不同題（依 semantic identity 判別）；再次答錯會重新累積。重點一旦完成，之後再次練習的錯誤不撤銷完成。原始 diagnostic／remediation、正誤與答案事件仍完整保留，不另形成掌握度 gate。

概念主要狀態只有「尚未開始／進行中／需要加強／已完成」。全部可檢測重點完成時，概念已完成；有錯題尚待完成則需要加強。題組的準備、失敗及本次練習結果不覆蓋概念狀態。測驗頁僅列出已有正式作答紀錄的概念，依既有完成狀態分為尚未完成與已完成；已完成概念提供「再次練習」；地圖側欄讀完完整重點後，可直接開啟或接續題組。

NO_SAFE_ASSESSMENT 或部分發布時省略的重點是系統能力限制，不算使用者答錯，也不形成永久補強 gate。有部分可檢測重點時，以這些重點判定該次完成；零可檢測時不自動完成，顯示「此概念目前無法提供可靠檢測」，允許繼續下一概念。已有題目而未作答的重點仍未完成。

完成狀態由 [learning_states.py](../backend/src/learning_adaptation/learning_states.py) 及歷史題組重建，不批次改寫過往答案。已完成 session 仍可開啟再次練習；單純閱讀或改變導覽焦點不重開 session。

## 學習活動與地圖區域

`GET /v1/learning-activity`（`learning-activity/v2`）由作答、概念卡複習與 Podcast 收聽紀錄即時彙總，不另存累計點數或任務狀態；只能讀自己的紀錄，以台灣日期為界。回傳連續天數、本週一到週日每天的作答／答對數、卡片複習數與實際收聽秒數、經驗值（XP）與等級、今日任務，以及徽章（`badges`）。讀取失敗時頁首與首頁隱藏相關數字，不顯示推測值。概念完成的作答重播在 API 程序內保留各版本學習計畫的精簡對應（以使用者、教材、版本與計畫雜湊為鍵），作答與可出題範圍每次即時讀取。

### 經驗值、等級與連續天數（規則 `xp-rules/v1`，可依需要修改）

規則常數集中在 [learning_activity.py](../backend/src/runtime/storage/learning_activity.py)；修改時一併更新版本字串與本節。

| 來源 | XP | 判定 |
| --- | --- | --- |
| 作答 | 答對 +10、答錯 +3 | 同一份教材的同一題（題目與正解相同的 semantic identity）只算第一次作答；重送與再次練習同一題不重算。 |
| 概念首次完成 | +30 | 依作答時間重播「重點完成」規則（初答正確即完成；答錯後須連續答對兩道不同題），概念的可出題重點全部完成的那一筆作答即為首次完成時間；目前確認無法出題的重點不列入。同一份教材的同一概念跨版本只算一次。 |
| 概念卡 | 每張 +2 | 卡片以「卡組＋概念」識別，同一張卡同一台灣日期只算一次；複習數仍逐次計算。 |
| Podcast | 每實際收聽滿 5 分鐘 +5 | 以每個台灣日期的實際收聽秒數合計，單日上限 60。 |

- 等級：第 n 級升到 n+1 需 100×n XP（1→2 需 100、2→3 需 200…）；回傳目前等級、本級已得 XP、升級所需 XP 與總 XP。沒有排行榜。
- 連續天數：當天有作答、概念卡複習，或實際收聽滿 1 分鐘（60 秒），即算有學習；今天尚未有活動時保留到今天結束。
- 計入上線前既有紀錄：作答自 10/16 起有逐筆紀錄、概念卡複習自 migration 0009 起；Podcast 收聽自 migration 0010 起才有紀錄。沒有紀錄的過去活動不補算、不推測；瀏覽器舊有的播放位置只上傳位置，收聽秒數為 0。
- 刪除教材或卡組時，相關紀錄隨之移除，XP 與等級會重新推導（可能下降）；概念首次完成只計入未刪除且知識結構可驗證的教材。
- 概念完成時間是重播推導值：與畫面的「已完成」使用同一個重點完成規則，但不重建題組補強流程的每個中間狀態；若日後確認某重點無法出題，完成時間依目前狀態重新推導。

### 今日任務

由真實資料推導、不另存，沒有對應資料的任務不顯示：

1. 概念卡：今天以前學過、現在到期或今天已複習的卡合計為目標，全部評到不再到期即完成（「忘了」的卡 10 分鐘後會再到期）；沒有到期卡時改為今天複習 5 張新卡（不足 5 張以現有張數為準）。兩者都沒有就不顯示。
2. 繼續學習：今天完成 1 次題組作答即完成；沒有進行中的學習（目前版本的 active／no_safe 學習）且今天也沒完成題組時不顯示。
3. Podcast：今天聽完任一集即完成；建議最近收聽、還有未聽完分集的節目。沒有未聽完的分集且今天也沒聽完時不顯示。

頁首顯示連續天數與等級（手機改顯示連續天數與 XP），點按進入「成就」頁（`/achievements`：等級卡、經驗值計算方式與徽章）；首頁只顯示今日任務，總覽數字與分項的本週節奏在「個人檔案」（`/profile`，另含帳號設定）。等級高於此瀏覽器上次看到的等級時播放一次升級動畫（尊重減少動態設定）；「上次看到的等級」存在 localStorage，只作顯示用途，第一次看到時只記下不播放。

### 徽章（規則 `badge-rules/v2`，可依需要修改）

徽章併入 `GET /v1/learning-activity` 的 `badges` 欄位（`rule_version` 與 `items`），與 XP 共用同一次計算（含概念完成的作答重播），不多一個請求。只由下表的真實紀錄即時推導，不存取得狀態、不補算沒有紀錄的過去活動；計入上線前既有紀錄（作答自 10/16 起）。規則常數 `BADGES` 在 [learning_activity.py](../backend/src/runtime/storage/learning_activity.py)，名稱與層級在 [Badges.tsx](../frontend/src/features/badges/Badges.tsx)；修改門檻或新增徽章時一併更新版本字串、API 模型、兩邊程式與本表。

同一計量的徽章是一個系列，門檻由低到高為層級 I～IV（畫面以銅、銀、金、鑽石呈現），每個層級是獨立的徽章項目：

| 系列（計量） | 層級：代號／名稱／門檻 | 資料來源 |
| --- | --- | --- |
| 作答（累計題數） | `first_answer` 初次作答 1；`answers_100` 百題挑戰 100；`answers_300` 題海航行者 300；`answers_1000` 千題大師 1000 | `answer_events` 逐筆作答（含重做） |
| 概念完成（累計個數） | `first_concept` 點亮概念 1；`concepts_25` 概念收藏家 25；`concepts_100` 知識建築師 100；`concepts_300` 知識大典 300 | 與 XP「概念首次完成」相同的作答重播；同一教材同一概念跨版本只算一次 |
| 教材完成（累計份數） | `first_material` 征服第一座島 1；`materials_3` 群島探險家 3；`materials_10` 群島領主 10 | `study_sessions` 狀態為 completed 與其完成時間；同一教材只算一次 |
| 概念卡複習（累計次數） | `cards_100` 卡片百回 100；`cards_500` 記憶練習生 500；`cards_2000` 過目不忘 2000 | `card_review_events` 逐次複習（同一張卡可重複計算） |
| Podcast 收聽（累計分鐘） | `listen_30_minutes` 用耳朵學習 30；`listen_180_minutes` 通勤聆聽者 180；`listen_600_minutes` 聆聽大師 600 | `podcast_listening_days` 的實際收聽秒數 |
| 連續學習（天） | `streak_3` 三日不間斷 3；`streak_7` 一週全勤 7；`streak_30` 月度堅持 30；`streak_100` 百日修行 100 | 與連續天數相同的活動日（作答、卡片複習或當日收聽滿 60 秒） |
| 等級 | `level_5` 進階探險家 5；`level_10` 資深航海士 10；`level_20` 傳奇學者 20 | `xp-rules/v1` 推導的每日 XP |

- 每個徽章回傳 `earned`、`earned_on`（台灣日期）、`progress` 與 `target`（進度不超過門檻）。累計型徽章的取得日期是累計第一次達到門檻的那一天；連續天數徽章是第一次連續達標的那一天，之後中斷仍保留，未取得時進度為目前連續天數；等級徽章是每日 XP 累計第一次達到門檻的那一天，進度為目前等級。目前所有條件都能推導日期；若日後規則推導不出日期，`earned_on` 為 null，畫面只顯示「已取得」。
- 刪除教材、卡組或清除教材時相關紀錄移除，徽章隨之重新判定（可能失去）；概念與教材完成只計入未刪除的教材。
- 「成就」頁每個系列一格：顯示目前層級、下一層的條件與真實進度，展開列出各層取得日期；上方另列「最接近的下一個徽章」（未取得中進度比例最高者）。讀取失敗時不顯示徽章區。前端不認得的代號不顯示。
- 有此瀏覽器還沒看過的新徽章時顯示一次提示（與升級同時發生時先顯示升級；尊重減少動態設定）。「看過的徽章」以 localStorage 保存，只作顯示用途；第一次在此瀏覽器讀到時只記下既有徽章，不提示。

### Podcast 收聽進度

migration 0010 新增 `podcast_episode_progress`（每集播放位置與首次聽完時間）與 `podcast_listening_days`（每集每天的實際收聽秒數），對 Podcast 外鍵 ON DELETE CASCADE。`GET／POST /v1/podcasts/{id}/progress` 只接受自己且已完成生成的節目；開啟時以伺服器的最近位置接續（跨裝置），伺服器沒有紀錄時才上傳此瀏覽器舊有的位置（`legacy`，不含收聽秒數）。

播放中每 15 秒、暫停、換集、聽完與離開頁面（keepalive）時回報位置與「距上次回報實際播放的牆鐘秒數」。伺服器依序處理同一學生的回報，只採計不超過距離上一筆採計的實際經過時間＋2 秒寬限、單次 60 秒及集長兩倍（0.5 倍速）的部分，重送、多分頁同時播放或離線補報不會灌水；超過上限的部分不採計。播放到距片尾 1 秒內或播放結束即標記該集聽完。刪除 Podcast 時移除播放位置，收聽紀錄保留到教材清除。

`GET .../knowledge-structures/{revision}/regions` 把概念分成地圖區域，只作呈現用途，不改寫知識結構或 hash。多來源教材依每個概念重點 Evidence 最常引用的來源檔分區（區名為去副檔名的檔名）；只有一個主要來源時依學習順序切成至多四段，`basis` 標為 `learning_order`，畫面註明「非教材章節」。前端只在區域剛好涵蓋地圖全部概念時分區，否則維持不分區的導覽。

### 章節分區（0012）

`knowledge_chapters` 是知識結構版本的衍生資料（主鍵 learner／material／structure_revision，隨版本刪除），不產生新版本，也不改卡片、進度、XP 或徽章。新版本發布時在同一交易排入 `pending`；背景 `studydy-chapters` worker 一次處理一份，有教材分析排隊或進行中時先等待。程式依學習順序送出概念名稱、引用頁碼與主要來源檔（`runtime/knowledge_chapters.py` 的固定提示，hash 存於 `prompt_sha256`），模型只回各章起點與名稱；每次請求的輸入估算＋輸出上限 ≤ 32K tokens，概念超過 600 個時依學習順序切窗並盡量在來源檔改變處切開。程式驗證每個概念剛好一章、章數在合理範圍、每章至少 3 個概念、名稱非空不重複不空泛且 ≤ 24 字；不合格帶原因補正一次，仍不合格只有該窗退回來源檔分區。全部窗合格為 `ready`、部分退回為 `fallback`、全部不合格或工作失敗為 `failed`，不無限重試；服務關閉時進行中的工作放回佇列，租約過期中斷兩次判定失敗。

regions API 有 `ready`／`fallback` 章節時回 `basis: "chapters"`，`partial` 標示部分退回；多來源教材另回 `groups`（來源檔分區），每章以 `group_id` 歸入成員最多的來源檔。前端在章節超過 24 個且有兩個以上島群時兩層呈現（來源檔＝島群、章節＝島，提供「跳到章節」選單），否則一層。沒有可用章節時沿用上述來源檔／學習順序分區。

既有教材的一次性回填（只排入佇列，不在命令內呼叫模型）：

```bash
docker compose --env-file .env -p studydy -f compose.yaml -f compose.tunnel.yaml \
  -f compose.app-update.yaml exec backend /app/backend/.venv/bin/python -m runtime.container_app \
  queue-chapters [--material <material_id> ...] [--requeue]
```

不帶 `--material` 時排入所有已發布、未清除且目前版本還沒有章節列的教材；`--requeue` 連已完成（含 `failed`）的也重新排入。

## 個人名稱與全站搜尋

`GET／POST /v1/profile` 讀寫學生自己的顯示名稱（migration 0008 新增的 nullable `learners.display_name`）。名稱經 NFC 正規化並去除前後空白，空字串視為清除；限 20 字、不得含控制字元或換行，DB 約束同步把關。名稱只顯示在頁首與首頁問候語，不進入 `learner-identity/v1`，未設定時沿用原問候。

`GET /v1/search?q=` 只查自己未刪除教材的名稱，以及各教材目前版本（head revision）的概念名稱與別名；資料來自每份教材一筆的 outline 讀取索引，不掃描重點全文。排序依完全相符、開頭相符、名稱包含、別名相符；概念最多 30 筆並以 `concepts_truncated` 標示。選取概念後開啟該教材地圖並直接顯示概念詳情；重點全文搜尋仍在各教材地圖內進行。

## 恢復與版本承接

Progress 與 resume 使用同一 DB snapshot，核對 session、run、知識結構版本、題組成員與事件序號。URL 可定位原題組；讀取、刷新與重新登入不產生題目或答案事件。

下一步由後端進度決定，前端提交 guidance_revision 套用操作。更新教材後，來源、文字及區塊一致且可唯一匹配的重點能承接證據；變更或匹配有歧義時不承接。

承接不複製答案事件，也不修改原題目、正誤、時間或版本。原題組仍依其固定版本讀取。

### 移到新版（卡組與學習進度）

教材重新分析或重新檢核產生新版本後，舊版的卡組、複習排程與學習照常保留，不會自動搬動。教材頁（地圖、卡組、Podcast、補充學習、來源各分頁上方）在學生仍有舊版卡組或學習時顯示「有新版本」，按「移到新版」先看預覽，確認後才承接。Podcast 維持建立時的版本，不承接。前端只在教材保留舊版本（`available_structures` 有 head 以外的版本）時才讀取預覽。

`GET /v1/materials/{id}/version-move` 回傳預覽（`version-move-preview/v1`）：可移動的舊版卡組（未刪除、已生成、尚未移過）與最近一個舊版學習，各自列出可對應的概念、無法對應的概念及原因、會沿用的複習排程數、可直接沿用的卡面數，以及維持舊版的 Podcast 數；`preview_digest` 綁定這份預覽。沒有可承接項目時 `card_sets` 為空、`study` 為 null。`POST` 同一路徑需要 Idempotency-Key 與預覽的 `preview_digest`、`to_revision`（目前 head）及要移動的卡組／是否移動學習：重送同一個鍵取得同一筆結果；預覽在確認前變了（教材又更新、另一個分頁已移動）回 `VERSION_MOVE_STALE`，前端重新讀取預覽。知識結構版本不可變，預覽在第一次完整驗證後於 API 程序內沿用由結構推導的概念名稱、順序與對應（千頁教材首讀約 6 秒，之後約 0.5 秒）；卡組、排程與學習進度每次即時讀取，確認承接時仍重新讀取並驗證完整結構。

概念對應規則（`map_concepts`，[source_identity.py](../backend/src/knowledge_map/source_identity.py)）：

1. 依原文區塊：舊概念各重點引用的教材原文區塊，以與既有承接相同的來源身分（原檔／normalized hash、來源頁碼、區塊順序、範圍與原文）比對。引用最多這些區塊的新概念若唯一，且涵蓋舊概念至少一半的區塊，就是對應概念。重新分析會改寫名稱與重點文字，但原文區塊不變，所以以此為主要依據。
2. 依名稱：沒有符合第 1 項時，舊概念名稱或別名（NFKC、不分大小寫、合併空白）與唯一一個新概念的名稱或別名相同。
3. 其他不承接並列給學生看：區塊分散到多個新概念（split）、名稱對到多個新概念（ambiguous）、找不到（not_found）。不猜測語意相近的名稱，也不拆分舊概念；多個舊概念可以對應同一個新概念（新版合併）。

卡組：在新版建立同名卡組，概念依舊卡組順序換成對應的新概念（合併的只留一張），無法對應的不放入。每張新卡沿用對應舊卡的複習排程（`card_review_states`；合併時取最早到期的一張，較保守）。來源輸入（重點文字、原文節錄與相鄰關係）完全相同的卡面直接沿用並換成新版的 Claim／Relation／Evidence ID，不呼叫模型；其餘卡面由既有卡片生成流程依新版內容製作，完成前新卡組不列入複習。舊卡組保留原卡面、排程與事件，標示「已移到新版」並不再列入複習佇列；新版卡組被刪除後，舊卡組可以再移一次。

學習進度：在新版建立（或沿用已有的）學習，從對應到的目前概念接著學。新概念對應到的所有舊概念在舊版都已完成時，新版標示為已完成（`study_session_moves.completed_concept_ids`，由進度推導的「曾完成概念」讀取）；只完成一部分的合併概念、或對應不到的已完成概念列為不承接，需在新版完成。內容沒有改寫的重點仍依上段規則沿用作答證據。舊版學習、題組與作答都不改寫，仍可依固定版本讀取。

XP、徽章與連續天數只由作答、複習與收聽事件推導，承接不新增事件，因此不會增加或重算。移到新版的卡片沿用最初那張卡的身分（`card_set_moves.concept_map`），同一天在舊卡與新卡各評一次仍只算一次卡片 XP，今日任務也不把它當成新卡；概念完成 XP 仍依作答重播，承接的完成不另給 XP。

## 概念卡間隔複習

每張卡以「卡組＋概念」識別，評分只有忘了／模糊／記得（規則 `card-review/v1`，以台灣日期為界）：忘了歸零並在 10 分鐘後再出現；模糊把間隔減半、至少 1 天，連續記得次數不變；記得依 1、3、7、14、30、60、120、240 天的階梯延長。到期時間取目標日期的台灣 00:00。

`card_review_events` 逐筆保存評分，`card_review_states` 保存每張卡目前的間隔與到期時間（migration 0009）。`POST /v1/card-sets/{id}/reviews` 需要 Idempotency-Key 與送出前看到的複習次數：重送同一個鍵取得同一筆結果；另一個分頁已評過時回 `CARD_REVIEW_CONFLICT`，不重複計次。`GET /v1/card-reviews/queue` 先列到期卡、再列從未複習的新卡，每次最多 20 張，並回傳各卡組的到期／新卡張數；只列生成完成、未刪除、教材未刪除且尚未移到新版的卡組。

概念移出卡組後排程保留但不列出，加回時沿用；卡組軟刪除後不再列出；教材清除實際刪除卡組時，排程與事件一併刪除。首頁「概念卡複習」與卡組頁的「今天要複習」共用同一個複習元件，翻卡後才能評分，卡背只列重點原文，完整卡面與來源仍在卡組中查看。

## 概念圖卡

新卡組保存選材與知識結構版本，依序準備來源、整理與設計卡面、核對來源，再開啟卡組。模型以整個概念為單位合併與取捨重點，選擇 focus／compare／flow／grid 版型、區塊順序、內建圖示及有來源支持的箭頭；優先一張，必要時最多三張處理不同核心問題。卡面依實際字型與可用寬度換行，標題、結論、區塊與畫布高度隨內容調整；不以後端估算字寬退件，也不截掉內容。次要細節可留在完整原文；顯示的結論仍須保留必要條件、否定、數值與主體責任。每個區塊與箭頭由模型的局部來源編號連回原 Claim／Relation／Evidence，避免整段改寫無法套入表格欄位。

來源核對只針對實質的事實、引用與關係錯誤；不因措辭偏好、例子多寡或未重述每段原文退件。格式或核對失敗時，保存實際候選卡面，只帶入目前未解決的回饋，再做一次定向修正；仍未通過就保留失敗狀態，可重試，不把長原文回填當成完成。工作分步保存，已完成觀念可續接，同擁有者、教材版本、設計政策與模型通道內可重用。既有卡組保留原卡面，不提供整組重新生成操作。

概念卡使用共用 `request_semantics`：`STUDYDY_TEXT_TEST_PROVIDER=codex-exec-luna` 是目前明確啟用的暫時 Luna 通道；未啟用時使用 runtime lock 的 Gemma，透過既有 `STUDYDY_SEMANTIC_BASE_URL`／Pod 連線層，不新增 SSH／Pod 連線程式。新工作保存模型、revision 與協定身分，通道中途改變時拒絕混用結果；另建卡組才綁定新設定。Gemma 回傳的 token 用量如實保存，Luna 未提供精確用量時只記錄估算與實際呼叫／耗時。

`needs_review` 在完整重點保留待確認提示。圖卡不會因繪製完成而取得品質驗收。保存版本讀取失敗時可重新讀取，不改用目前的教材版本；來源入口沿用該版本的 resolver。預覽不經 PNG 編碼／解碼，也不提供放大功能；下載直接編碼目前 Canvas 的相同像素。卡組首次只讀取 8 個觀念及必要的相鄰概念、關係與來源，背景預取下一批；跳選直接取得目標批次，不下載整份知識結構。文字最多保留目前及鄰近使用的三批；背景只預繪下一張，帳號工作階段在記憶體最多保留最近 8 張 Canvas（約 28 MiB 像素），依教材版本、概念、精簡文字及頁碼重用；失敗不留快取。快取隨帳號 API 物件釋放，重新整理或帳號切換後重新產圖，不寫入伺服器圖片或瀏覽器持久儲存；經核對的卡面設計 JSON 隨卡組保存，只在同一擁有者、教材版本、設計政策與模型通道內重用。舊卡組保留原文顯示，不因升級自動觸發模型。不執行教材提供的 HTML、JavaScript 或 SVG。

卡面使用固定比例，集中顯示標題、核心說明、至多四個重點節錄與小圖。左側選概念，右側單卡預覽；完整條件與全部來源可另開詳細面，不以節錄取代教材。

`card_count` 統一表示包含續圖的實際張數；概念數由選材與生成進度取得。列表或複習頁按卡組版本保存每個觀念的續頁張數，全部備齊後彙總 `card_count`；後續列表只讀摘要，不再下載卡片全文、整份知識結構或繪圖模組。跳選尚未備齊前段頁碼的卡片時顯示觀念內頁碼，不猜測全組頁碼。尚未完成精簡時只顯示生成進度；既有卡組首次補算一次。改名保留張數，選材變更清除重算；保存失敗提供重試，不將未保存結果當成成功。分頁政策更新時須同步前後端的 `layout_policy`，並以 migration 將既有 `card_count` 清為 NULL，再使用同一套排版補算。

建立卡組時，由已驗證的保留版 KS 建立按概念查詢的文字投影；同版本的多個卡組共用。0026 migration 新增索引與概念續頁計數，舊卡組可一次補建，不觸發模型。每次分批讀取核對 owner、卡組版本、來源綁定及本批投影 hash，來源連結沿用原 resolver；原文、頁碼、區塊與完整關係來源不截斷。索引隨 KS 的保留／清理生命週期，不另建圖片倉庫。

## 教材文字與語音問答

文字與語音辨識後的問題共用 RAG 路徑。Luna 先依問題與必要追問上下文規劃一到四組精確檢索術語，再連同原問題查詢已保存的索引；查詢規劃不提供答案依據。檢索補鄰接內容與同概念資料，完全相同的原文去重但保留各來源。對話按 token 預算保留近期完整輪次，超額時才將較早內容與既有摘要合併壓縮；摘要與近期對話共用原歷史預算，沒有固定三輪限制。摘要保留目標、條件、修正與未解問題，只供還原指涉，教材事實仍須檢索原文支持。原始對話不刪除，摘要為有損壓縮，不保證所有舊細節均能保留。

Luna 逐段回答並引用本輪原文，獨立核對各段。核對可刪去未支持的附加主張或修正適用範圍，保留有依據的核心步驟；不能藉修正新增事實。資料不足時最多補查一次，同時保留回答與核對階段提出的精確術語，各子問題保有取材名額。保留已通過核對的回答，具體指出未補足部分，不因一個次要缺口丟棄全部答案。新回答保存 `material-answer/v2` 與 passage 引用，不重建舊 claim 索引或轉接舊回答。

問答原文預算為 7,500 個估算 token；歷史合計 1,200，其中摘要最多 550；整次提示與輸出 schema 上限 12,000，另保留模型回答空間。摘要按批次保存處理位置，後續只壓縮新超額的輪次，不重送全部舊對話。使用 o200k 作估算，不把它當 Luna 實際 tokenizer 用量。取材、模型呼叫（含摘要）、各次輸入估算及壓縮前後歷史大小保存在回答的診斷欄位，不顯示給一般學習操作。

錄音先辨識文字，再走同一問答路徑；純文字不呼叫 TTS。答案朗讀失敗時保留文字與引用，重試只重做語音。取消與離開頁面沿用既有媒體清理與工作租約，不跨帳號保留音訊。

Podcast 依選定概念及關係規劃分集，透過同一索引取得各集引用與同頁鄰接脈絡。原文區塊只放一次，來源編號連回所選概念；與原文完全相同的重點不再重複放入提示，獨立摘要則保留。必要原文全部保留後，再以剩餘容量補鄰接內容；非連續片段明示缺口。不掃描整份教材作每集 context，不因容量不足截斷必要引用或更動既有腳本。

分集保留完整重點，以每集至多 32 個來源重點、8,000 個原文估算 token、10,000 個來源與脈絡合計估算 token 規劃，不再以 2,400 字元拒絕長重點。單一重點的必要原文仍無法容納時，回報 `PODCAST_SOURCE_TOO_LARGE`。教材索引建立成功不代表任意概念選取都能生成 Podcast；模型品質仍須檢查實際講稿與引用。
